# 06. 문제 해결 패턴

## 투 포인터와 슬라이딩 윈도

투 포인터는 두 인덱스의 관계로 탐색 공간을 줄인다. 정렬 배열의 두 수 합은 합이 작으면 왼쪽, 크면 오른쪽 포인터를 움직여 `O(n)`에 찾는다.

슬라이딩 윈도는 연속 구간이 한 칸 이동할 때 빠지는 값과 들어오는 값만 반영한다. 고정 길이 최대 합은 `O(n)`이다. 합 조건으로 창을 줄이는 방식은 보통 원소가 음이 아닌 등 단조성이 필요하다. 음수가 있으면 창을 줄였을 때 합의 방향을 예측할 수 없다.

## 누적 합과 차분 배열

`prefix[i+1] = prefix[i] + a[i]`로 만들면 반열린 구간 `[left,right)`의 합은 `prefix[right]-prefix[left]`로 `O(1)`에 답한다. 전처리는 `O(n)`이다.

범위에 값을 여러 번 더하고 마지막 결과만 필요하면 차분 배열에 시작점 `+x`, 끝 다음 `-x`를 기록한 뒤 한 번 누적한다. 2차원 누적 합도 같은 포함-배제 원리로 사각형 합을 구한다.

## 분할 정복

문제를 독립적인 작은 문제로 나눠 재귀적으로 해결하고 합친다. 병합 정렬은 두 절반을 정렬한 뒤 `O(n)`에 병합하여 `T(n)=2T(n/2)+O(n)=O(n log n)`이 된다. 부분 문제가 겹치지 않는 점이 전형적인 DP와의 차이다.

## 그리디

그리디는 매 단계의 지역 최선 선택을 되돌리지 않는다. 빠르지만 “그럴듯함”은 증명이 아니다.

- 교환 논증: 최적해의 선택을 그리디 선택으로 바꿔도 손해가 없음을 보인다.
- 앞서가기 논증: 매 단계 그리디가 다른 해보다 뒤처지지 않음을 보인다.
- 대표 예: 종료 시간이 가장 빠른 회의부터 선택하는 구간 스케줄링, Kruskal MST.

동전 거스름돈은 임의 화폐 체계에서는 그리디가 실패한다. 예를 들어 동전 `1,3,4`로 `6`을 만들 때 그리디는 `4+1+1`이지만 최적은 `3+3`이다.

## 완전 탐색과 비트마스크

완전 탐색(brute force)은 가능한 답을 빠짐없이 생성해 검사한다. 가장 단순한 정답 기준이 되므로 작은 무작위 입력에서 최적화한 알고리즘과 결과를 비교하는 데도 유용하다. `n`개 원소의 모든 부분집합은 `0`부터 `(1 << n)-1`까지의 비트로 표현할 수 있고 `O(n·2^n)`, 모든 순열은 `O(n·n!)` 정도가 필요하다. 입력 제한을 먼저 확인하고, 대칭 제거·정렬·가지치기·중복 상태 저장으로 줄인다.

## 백트래킹

백트래킹은 선택 → 재귀 → 선택 취소를 반복하며 유효하지 않은 가지를 일찍 자른다.

```text
search(state):
    if complete(state): record answer; return
    for choice in candidates(state):
        if invalid(choice): continue
        apply(choice)
        search(state)
        undo(choice)
```

순열, 조합, N-Queens, 스도쿠가 대표적이다. 최악은 여전히 지수 시간이므로 중복 상태가 많다면 메모이제이션이나 DP를 고려한다.

## 동적 계획법(DP)

DP(Dynamic Programming, 동적 계획법)는 겹치는 부분 문제의 답을 저장한다.

1. 상태: `dp[i]`가 정확히 무엇을 뜻하는가?
2. 전이: 더 작은 상태에서 어떻게 오는가?
3. 초기값: 가장 작은 문제의 답은 무엇인가?
4. 계산 순서: 전이에 필요한 상태가 먼저 계산되는가?
5. 결과: 어느 상태가 최종 답인가?

예제의 `climbStairs(n)`은 `dp[i] = i번째 계단에 도달하는 방법 수`, 전이는 `dp[i-1]+dp[i-2]`다. 전체 배열 대신 직전 두 값만 필요하므로 공간을 `O(n)`에서 `O(1)`로 줄인다.

대표 유형은 0/1 배낭, 최장 공통 부분 수열, 최장 증가 부분 수열, 격자 경로, 구간 DP, 트리 DP다. 그리디와 달리 가능한 이전 선택들의 최적값을 비교해 저장한다.
