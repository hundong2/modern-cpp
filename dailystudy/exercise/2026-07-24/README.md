# 2026-07-24 — C++20 코루틴으로 지연 실행 `Task` 만들기

## 오늘의 목표

오늘은 **호출하는 순간 실행하지 않고, 필요할 때 한 단계씩 재개하는 작업 객체**를 만든다. 핵심 문법은 `co_yield`, `std::coroutine_handle`, `promise_type`이며, 아키텍처 관점에서는 다음 역할을 분리한다.

- `Sequence<T>`: 코루틴 프레임의 수명과 재개를 책임지는 소유 객체
- `promise_type`: 코루틴 본문과 호출자 사이의 약속(값 전달, 시작/종료 방식)
- 애플리케이션 코드: 생성된 수열을 순회하며 결과만 사용

코루틴은 “함수가 잠시 멈췄다가 다시 시작한다”는 문법을 제공하지만, 프레임 소유권을 자동으로 해결해 주지는 않는다. 이 예제에서는 `Sequence<T>`가 핸들을 단독 소유하고 소멸자에서 프레임을 파괴한다.

## 먼저 알아둘 기초 문법

- `int count{3};`은 기본 정수 타입 `int` 변수를 중괄호로 초기화한다. 중괄호 초기화는 위험한 축소 변환을 더 엄격히 막는다.
- `const`가 붙은 객체는 그 이름을 통해 값을 바꿀 수 없다.
- `T&`는 기존 객체의 별명인 lvalue 참조, `T&&`는 문맥에 따라 임시 객체나 이동 가능한 객체에 바인딩하는 참조다.
- 포인터는 주소를 저장할 수 있고 `nullptr`일 수 있지만, 참조는 이미 존재하는 객체에 바인딩한다.
- `struct`의 기본 접근은 `public`, `class`의 기본 접근은 `private`다. 예제는 의도를 분명히 하려고 접근 지정자를 직접 쓴다.
- 생성자는 클래스 이름과 같고 **반환형을 쓰지 않는다**. 멤버 초기화 목록은 생성자 본문보다 먼저 멤버를 초기화한다.
- `explicit` 생성자는 인자 하나가 객체로 몰래 변환되는 것을 막는다. `Sequence<int> s{handle};` 같은 직접 초기화는 허용된다.
- `using Handle = std::coroutine_handle<promise_type>;`은 긴 타입의 별칭이다. `<promise_type>`과 `<int>`는 템플릿 인자다.

## 값 범주와 실제 식

- 이름이 있는 `sequence`와 `value`는 주소를 식별할 수 있는 **lvalue**다.
- `make_countdown(3)` 호출 결과는 이름 없는 `Sequence<int>` 임시 객체인 **prvalue**다. 변수 초기화에 바로 쓰면 C++17 이후 보장된 복사 생략으로 목적 객체가 직접 만들어진다.
- `std::move(other.handle_)`는 실제 이동 명령이 아니라 `other.handle_`를 **xvalue**로 바꾸는 캐스트다. 이 예제의 이동 생성자는 핸들 값을 넘기고 원본을 비운다.
- `const int& ref = sequence.value();`는 기존 멤버에 대한 lvalue 참조 바인딩이다. 코루틴이 다시 재개되어 값을 바꾸기 전까지만 같은 값을 관찰한다.
- 코루틴 지역 변수와 `promise_type`은 코루틴 프레임 안에서 살아 있다. `Sequence`가 소멸하며 `destroy()`를 호출하면 그 수명도 끝난다.

## 기계 실행 관점

일반적인 구현에서 코루틴 호출은 프레임 저장 공간 확보, 상태 저장, 재개 지점 판별, 함수 호출을 동반할 수 있다. `resume()`은 저장된 상태를 읽고 다음 재개 지점으로 간접 분기하며, `done()`은 완료 상태를 읽어 비교한다. 가상 함수 예제는 가상 함수 테이블을 통한 간접 호출이 될 수 있다. 다만 정확한 로드·저장·비교·조건 분기·호출 형태와 코루틴 최적화/할당 제거 여부는 CPU, ABI, 컴파일러, 표준 라이브러리, 최적화 옵션에 따라 달라지므로 특정 어셈블리 명령으로 단정하지 않는다.
