# 두 포인터와 슬라이딩 윈도우

## 정의와 적용 조건

두 포인터는 배열이나 문자열에서 두 인덱스를 한 방향으로 움직이며 후보 구간을 효율적으로 관리하는 기법이다. 슬라이딩 윈도우는 두 포인터 사이의 연속 구간과 그 합·빈도 같은 집계값을 함께 유지한다. 구간을 늘리거나 줄일 때 조건의 변화 방향을 예측할 수 있어야 한다. BOJ 1806에서는 모든 원소가 양수라 합의 단조성이 보장된다.

## 핵심 아이디어와 불변식

현재 창을 반열린 구간 `[left, right)`로 두고 `sum`을 그 구간 합으로 유지한다. 오른쪽 원소를 넣으면 `right`가 증가하고, 왼쪽 원소를 빼면 `left`가 증가한다. 불변식은 `sum == a[left] + ... + a[right-1]`이다. 양수 수열에서는 오른쪽 확장이 합을 늘리고 왼쪽 축소가 합을 줄이므로, 이미 버린 왼쪽 위치로 돌아갈 필요가 없다.

## 단계별 절차

1. 두 인덱스와 창의 집계값을 0으로 초기화한다.
2. 오른쪽 원소를 창에 추가한다.
3. 조건을 만족하는 동안 현재 길이로 답을 갱신하고 왼쪽 원소를 제거한다.
4. 오른쪽 끝까지 반복한다.
5. 답을 한 번도 갱신하지 않았다면 문제에서 요구한 실패 값을 반환한다.

## 의사 코드

```text
left = 0, sum = 0, best = infinity
for right = 0 .. n-1
    sum += a[right]
    while sum >= target
        best = min(best, right-left+1)
        sum -= a[left]
        left += 1
return best가 infinity이면 0, 아니면 best
```

## 컴파일 가능한 C++ 뼈대

```cpp
#include <algorithm> // std::min
#include <limits>    // numeric_limits
#include <vector>    // vector

int shortest_at_least(const std::vector<int>& values, long long target) {
    int left{};                              // 왼쪽 인덱스를 0 초기화한다.
    long long sum{};                         // 큰 합을 담도록 long long을 쓴다.
    int best{std::numeric_limits<int>::max()}; // 답 없음 센티널이다.
    for (int right{}; right < static_cast<int>(values.size()); ++right) {
        sum += values[static_cast<std::size_t>(right)]; // 오른쪽 원소를 한 번 넣는다.
        while (sum >= target) {              // 조건을 만족하면 왼쪽을 줄인다.
            best = std::min(best, right - left + 1);
            sum -= values[static_cast<std::size_t>(left++)]; // 원소를 빼고 포인터를 이동한다.
        }
    }
    return best == std::numeric_limits<int>::max() ? 0 : best;
}

int main() {
    return shortest_at_least(std::vector<int>{5, 10}, 15) == 2 ? 0 : 1;
}
```

## 정확성 근거

각 반복에서 `sum`은 정확히 현재 창 원소의 합이다. 합이 목표보다 작으면 양수 조건상 왼쪽을 줄여서는 합이 커질 수 없으므로 오른쪽을 확장하는 선택만 유효하다. 합이 목표 이상이면 현재 구간은 후보이고, 왼쪽을 하나씩 제거해 조건이 깨질 때까지 진행하므로 그 오른쪽 끝을 공유하는 모든 유효 후보와 최소 길이를 검사한다. 모든 오른쪽 끝을 처리하므로 전역 최소 길이도 반드시 갱신된다.

## 시간·공간 복잡도

각 원소는 창에 한 번 들어오고 최대 한 번 나가므로 시간은 `O(N)`이다. 입력을 벡터에 저장하면 공간은 `O(N)`이고, 두 인덱스·합·답만 세는 알고리즘 추가 공간은 `O(1)`이다.

## 흔한 실수

- 음수나 일반 정수 수열에도 합의 단조성이 있다고 가정한다.
- `int` 합이 오버플로할 수 있는데 더 넓은 타입을 쓰지 않는다.
- 길이 계산에서 `right - left + 1`의 `+1`을 빠뜨린다.
- 조건을 만족한 뒤 한 번만 줄여 더 짧은 후보를 놓친다.
- 답 없음 센티널을 그대로 출력한다.

## 변형

- 고정 길이 창: 새 원소를 넣을 때 창 크기를 넘으면 왼쪽 원소를 즉시 뺀다.
- 빈도 창: 합 대신 `array`나 해시 맵에 문자·값 빈도를 유지한다.
- 양끝 합 문제: 정렬된 배열의 양 끝 포인터를 합 비교 결과에 따라 안쪽으로 옮긴다.
- 음수가 있는 부분합: 누적 합과 정렬 구조·단조 덱 등 문제 조건에 맞는 다른 기법이 필요하다.
