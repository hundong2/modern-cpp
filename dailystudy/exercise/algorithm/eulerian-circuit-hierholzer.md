# 오일러 회로와 Hierholzer 알고리즘

## 정의

그래프의 **오일러 회로(Eulerian circuit)** 는 어떤 정점에서 출발해 모든 간선을 정확히 한 번씩 사용하고
출발 정점으로 돌아오는 닫힌 보행이다. 정점은 여러 번 방문해도 되지만 간선은 두 번 사용할 수 없다.

Hierholzer 알고리즘은 아직 사용하지 않은 간선을 따라가다가 더 갈 수 없는 정점을 답의 뒤쪽에 확정하고,
그 결과를 역순으로 읽어 오일러 회로를 만드는 선형 시간 알고리즘이다. 무방향 그래프뿐 아니라 간선 방향과
차수 조건을 바꾸면 방향 그래프에도 적용할 수 있다.

무방향 그래프가 지정된 시작점 `s`에서 오일러 회로를 갖기 위한 조건은 다음과 같다.

1. 간선이 하나라도 있다면 `s`의 차수는 0이 아니어야 한다.
2. 차수가 0보다 큰 모든 정점이 `s`와 같은 연결 요소에 있어야 한다.
3. 모든 정점의 차수가 짝수여야 한다.

고립 정점은 간선을 사용할 의무가 없으므로 연결 조건에서 제외한다. 간선이 0개인 입력을 허용하는 문제라면
정점 `s` 하나만 출력하는 길이 0 회로를 별도로 허용할 수 있다.

## 적용 조건

- 모든 **간선**을 한 번씩 사용해야 하고 시작점과 끝점이 같아야 할 때 적용한다.
- 우편 배달, 도로 점검, 네트워크 링크 순회, 도미노 연결처럼 간선 사용 순서가 답인 문제에 알맞다.
- 정점 방문을 한 번으로 제한하는 해밀턴 경로 문제와는 다르다. 정점을 반복 방문해도 된다.
- 무방향 그래프에서 시작점과 끝점이 달라도 되는 오일러 경로는 홀수 차수 정점이 정확히 2개인 변형이다.
- `O(V+E)`가 필요한 큰 그래프에 적합하다. 매번 다리를 피하는 Fleury 방식은 구현에 따라 훨씬 느려질 수 있다.

## 존재 조건을 빠르게 판정하는 법

무방향 간선 하나는 양 끝 정점의 차수를 각각 1씩 증가시키므로 차수 합은 항상 `2E`다. 닫힌 회로가 한
정점에 들어올 때마다 다른 미사용 간선으로 나가야 하므로 각 정점의 사용 차수는 짝수다. 따라서 짝수 차수는
필요조건이다.

하지만 짝수 차수만으로는 충분하지 않다. 예를 들어 정점 1을 포함한 삼각형과 정점 1에서 떨어진 또 다른
삼각형은 모든 차수가 2지만 한 번의 경로로 두 컴포넌트의 간선을 모두 쓸 수 없다. 다음 두 방법 중 하나로
연결 조건도 확인해야 한다.

- DFS/BFS로 시작점에서 차수가 양수인 모든 정점에 도달하는지 검사한다.
- 시작점에서 Hierholzer를 실행한 뒤 생성된 경로 정점 수가 정확히 `E+1`인지 검사한다.

두 번째 방식은 별도 방문 배열과 탐색을 생략한다. Hierholzer가 소비한 간선 수를 `k`라 하면 결과에는
정점이 `k+1`개 들어가므로, 결과 크기가 `E+1`인 것은 모든 간선을 소비했다는 뜻이다.

## 핵심 아이디어와 불변식

### 간선 ID

무방향 간선 `(u,v)`는 인접 목록에 `u -> v`, `v -> u` 두 항목으로 저장한다. 두 항목에 같은 `edge_id`를
붙이고 `used[edge_id]` 하나를 공유해야 한다. 한쪽에서 간선을 선택하는 순간 id를 사용 처리하면 반대쪽 항목을
나중에 만나도 다시 선택하지 않는다.

정점 방문 배열로는 이 일을 대신할 수 없다. 오일러 회로에서는 같은 정점을 여러 번 방문해야 하며, 평행
간선도 서로 다른 간선으로 세어야 한다. 끝점 쌍만으로 간선을 식별하는 방식도 평행 간선을 구분하지 못한다.

### 명시적 스택과 역순 경로

`stack`은 현재 이어 가는 보행을 담는다. 스택 꼭대기 정점에 미사용 간선이 있으면 그 간선을 사용 처리하고
이웃을 스택에 넣는다. 미사용 간선이 없으면 그 정점을 꺼내 `reversed_route` 뒤에 넣는다. 따라서 먼저 막힌
정점이 답에서는 나중에 나타나며, 마지막에 `reversed_route`를 거꾸로 읽어야 한다.

유지할 핵심 불변식은 다음과 같다.

1. `used[id] == true`인 간선만 현재 보행 또는 확정된 부분 회로에 포함되고, 각 id는 거짓에서 참으로 최대 한 번만 바뀐다.
2. 스택의 인접한 두 정점 사이는 방금 선택한 서로 다른 사용 간선으로 연결된다.
3. `cursor[v]`보다 앞선 인접 항목은 이미 선택했거나 같은 id의 반대쪽 항목이 먼저 사용되었다.
4. 정점 `v`를 `reversed_route`에 넣는 순간에는 `v`에 남은 미사용 간선이 없다.
5. 짝수 차수 그래프에서 시작점에서 도달 가능한 모든 간선을 처리하면 스택의 보행은 닫힌 부분 회로들로 분해되며, pop 순서는 그 회로들을 올바르게 이어 붙이는 역순이다.

`cursor[v]`를 단조 증가시키는 것이 선형 시간의 핵심이다. 매번 인접 목록 처음부터 사용 가능한 간선을
찾으면 같은 항목을 반복해서 검사해 별 모양 그래프 등에서 제곱 시간에 가까워질 수 있다.

## 단계별 절차

1. 각 입력 무방향 간선에 `0..E-1`의 고유 ID를 준다.
2. 두 끝점의 인접 목록에 같은 ID와 반대편 정점을 저장한다.
3. 모든 정점의 인접 목록 크기가 짝수인지 검사한다. 하나라도 홀수면 실패다.
4. 정점별 인접 목록 커서 `cursor`와 간선별 사용 배열 `used`를 0으로 초기화한다.
5. 지정된 시작점 `s`를 명시적 스택에 넣는다.
6. 스택이 빌 때까지 다음을 반복한다.
   - 꼭대기 정점 `v`의 커서를 이미 사용된 간선들 너머로 이동한다.
   - 미사용 간선 `(v,to,id)`가 있으면 `used[id] = true`로 바꾸고 `to`를 스택에 넣는다.
   - 더 이상 미사용 간선이 없으면 `v`를 역순 경로에 넣고 스택에서 제거한다.
7. 역순 경로 크기가 `E+1`인지 확인한다. 작다면 시작점과 분리된 간선이 있으므로 실패다.
8. 역순 경로를 뒤에서 앞으로 출력한다.

## 의사코드

```text
for id = 0 .. E-1:
    (u, v) 입력
    adjacency[u].push((v, id))
    adjacency[v].push((u, id))

for v = 1 .. V:
    if degree(v) is odd:
        IMPOSSIBLE

cursor[1..V] = 0
used[0..E-1] = false
stack = [start]
reversed_route = []

while stack is not empty:
    v = stack.back()

    while cursor[v] < adjacency[v].size and
          used[adjacency[v][cursor[v]].id]:
        cursor[v] += 1

    if cursor[v] == adjacency[v].size:
        reversed_route.push_back(v)
        stack.pop_back()
    else:
        edge = adjacency[v][cursor[v]]
        cursor[v] += 1
        used[edge.id] = true
        stack.push_back(edge.to)

if reversed_route.size != E + 1:
    IMPOSSIBLE
else:
    reversed_route를 뒤에서 앞으로 출력
```

## C++ 뼈대

아래 뼈대는 핵심 자료구조와 반복형 루프만 보여 준다. 실제 제출 코드에서는 입력 범위 검사, 짝수 차수
검사, 시작점 정책과 출력 형식을 문제 조건에 맞춰 붙인다. `std::reverse`를 쓰지 않고 역인덱스로 읽으면
추가 알고리즘 호출 없이 같은 결과를 얻는다.

```cpp
#include <cstddef>
#include <vector>

struct Edge {
    int to{};
    int id{};
};

using Graph = std::vector<std::vector<Edge>>;

// 반환 벡터는 아직 역순이다. 크기가 edge_count+1인지 호출자가 검사한다.
std::vector<int> build_reversed_circuit(
    const Graph& graph, int edge_count, int start) {
    std::vector<std::size_t> cursor(graph.size(), std::size_t{0});
    std::vector<char> used(static_cast<std::size_t>(edge_count), char{0});
    std::vector<int> stack;
    std::vector<int> route;
    stack.reserve(static_cast<std::size_t>(edge_count) + std::size_t{1});
    route.reserve(static_cast<std::size_t>(edge_count) + std::size_t{1});
    stack.push_back(start);

    while (!stack.empty()) {
        const int vertex{stack.back()};
        const auto& edges{graph[static_cast<std::size_t>(vertex)]};
        std::size_t& next{cursor[static_cast<std::size_t>(vertex)]};

        while (next < edges.size() &&
               used[static_cast<std::size_t>(edges[next].id)] != char{0}) {
            ++next;
        }

        if (next == edges.size()) {
            route.push_back(vertex);
            stack.pop_back();
        } else {
            const Edge edge{edges[next]};
            ++next;
            used[static_cast<std::size_t>(edge.id)] = char{1};
            stack.push_back(edge.to);
        }
    }
    return route; // 이름 있는 지역 소유 객체는 NRVO 대상이며, 실패해도 이동 반환이 가능하다.
}

// 사용 예: route.size()==E+1을 확인한 뒤 역인덱스로 route[i-1]을 읽는다.
```

## 정확성 근거

### 보조정리 1: 어떤 간선도 두 번 선택되지 않는다

간선을 선택하기 직전에 `used[id]`가 거짓인지 확인하고 즉시 참으로 바꾼다. 같은 무방향 간선의 두 인접
항목은 하나의 id를 공유한다. 이후 어느 끝점에서 그 id를 만나도 건너뛰므로 같은 간선은 최대 한 번 선택된다.

### 보조정리 2: 도달 가능한 미사용 간선은 빠뜨리지 않는다

`cursor[v]`는 이미 처리된 항목만 지나 앞으로 이동한다. 정점 `v`를 스택에서 제거하는 경우는 커서가
인접 목록 끝에 도달했을 때뿐이다. 이때 `v`의 모든 인접 항목은 이미 사용된 id다. 따라서 시작점에서 현재
보행을 통해 도달한 컴포넌트 안에서 선택 가능한 간선을 임의로 빠뜨리고 정점을 확정하지 않는다.

### 보조정리 3: 역순 목록을 뒤집으면 선택한 간선들의 연속된 닫힌 보행이다

스택에 이웃을 넣을 때마다 두 연속 정점 사이에 새 간선 하나가 생긴다. 정점은 더 나갈 간선이 없을 때만
pop된다. 모든 차수가 짝수라면 시작점이 아닌 정점에 새 간선으로 들어온 횟수만큼 나갈 미사용 간선이 짝을
이룬다. 따라서 도중에 열린 끝점이 확정될 수 없고 부분 보행은 시작점으로 닫힌다.

이미 발견한 회로의 정점에서 나중에 다른 미사용 회로를 돌게 되면, 스택 pop 순서는 새 회로의 정점들을 그
정점 바로 뒤에 배치한다. 이는 Hierholzer의 “부분 회로 끼워 넣기”와 같다. pop 순서가 반대이므로 목록을
뒤집으면 선택한 간선들이 끊김 없이 이어진 닫힌 보행이 된다.

### 보조정리 4: 경로 크기 `E+1`은 모든 간선 사용을 보장한다

서로 다른 간선 `k`개를 이은 보행에는 시작 정점을 포함해 정점 항목 `k+1`개가 있다. 보조정리 1에 의해
중복 선택은 없으므로 결과 크기가 `E+1`이면 정확히 `E`개의 서로 다른 입력 간선을 선택했다. 입력 간선도
총 `E`개이므로 빠진 간선이 없다. 반대로 시작점과 분리된 간선이 있다면 그 id는 선택될 수 없어 결과 크기가
`E+1`보다 작다.

### 정리

알고리즘이 경로를 출력했다고 하자. 홀수 차수 정점이 없고 결과 크기가 `E+1`이므로, 보조정리 3에 의해
시작점에서 끝나는 닫힌 보행이며 보조정리 4에 의해 모든 입력 간선을 사용한다. 보조정리 1에 의해 어느
간선도 두 번 쓰지 않는다. 따라서 출력은 지정된 시작점에서 출발해 그곳으로 돌아오는 올바른 오일러 회로다.

존재하는 오일러 회로가 있는데 실패한다고 가정하자. 존재성 때문에 모든 차수는 짝수라서 차수 검사에서
실패하지 않는다. 또한 모든 양의 차수 정점은 시작점과 연결되어 있다. 보조정리 2에 따라 그 컴포넌트의 모든
간선을 처리하므로 결과 크기는 `E+1`이다. 따라서 크기 검사도 실패하지 않아 모순이다.

## 시간·공간 복잡도

- 인접 목록 구성: 무방향 간선당 항목 2개이므로 `O(V+E)` 시간과 공간
- 짝수 차수 검사: `O(V)` 시간
- Hierholzer 순회: 각 정점 커서가 단조 증가해 인접 항목 `2E`개를 각각 최대 한 번 검사하므로 `O(V+E)` 시간
- `used`, `cursor`, 스택, 결과 경로: 합쳐서 `O(V+E)` 추가 공간
- 전체: `O(V+E)` 시간, `O(V+E)` 공간

스택과 결과 경로에는 최악 `E+1`개 정점이 들어갈 수 있다. 재귀 DFS 형태로 흉내 내면 깊이가 `O(E)`가 될
수 있으므로 `E=200,000` 수준에서는 명시적 벡터 스택이 안전하다.

## 흔한 실수

- **정점 방문 배열을 사용한다.** 오일러 회로는 같은 정점을 반복 방문해야 하므로 간선 ID별 사용 상태가 필요하다.
- **무방향 간선의 양쪽 항목에 서로 다른 ID를 준다.** 실제 거리 하나가 두 번 사용된다.
- **차수 짝수만 검사한다.** 시작점과 분리된 짝수 차수 컴포넌트를 놓친다. 연결 탐색 또는 `route.size()==E+1` 검사가 필요하다.
- **시작점을 임의의 양의 차수 정점으로 바꾼다.** 문제에서 시작·끝 정점 1을 요구하면 반드시 1에서 시작해야 한다.
- **인접 목록에서 원소를 반복해서 erase한다.** 이동 비용과 반복자 무효화가 생긴다. 정점별 커서를 쓰는 편이 단순하고 선형이다.
- **사용된 항목을 건너뛸 때 커서를 증가시키지 않는다.** 같은 항목에서 무한 루프가 난다.
- **새 간선을 선택한 뒤 id를 늦게 사용 처리한다.** 반대쪽 항목이 다시 선택될 수 있다. 스택 push 전에 표시한다.
- **pop 순서 그대로 출력한다.** 만들어진 목록은 역순이므로 뒤집거나 역인덱스로 출력해야 한다.
- **재귀를 사용한다.** 긴 회로에서 호출 스택이 넘칠 수 있다.
- **정점 수를 답 길이로 착각한다.** 오일러 회로의 출력 길이는 서로 다른 정점 수가 아니라 `E+1`이다.
- **평행 간선을 끝점 쌍으로만 표시한다.** 두 간선을 하나로 합쳐 버린다. 고유 ID가 안전하다.

## 대회 실전 팁

1. 입력을 읽을 때 바로 `edge_id`를 루프 인덱스로 부여하면 별도 맵이 필요 없다.
2. 인접 목록 정렬이 요구되지 않으면 정렬하지 않는다. 임의의 유효 회로는 입력 순서 그대로도 얻을 수 있다.
3. 스택과 결과에 `E+1` capacity를 예약하면 큰 입력에서 반복 재할당을 피할 수 있다.
4. 답 검증을 `route.size()==E+1` 하나로 하면 별도 연결성 DFS를 줄여 실수 표면을 작게 만든다.
5. 자기 루프를 허용하는 변형에서는 같은 정점 인접 목록에 같은 id 항목이 두 번 들어가야 차수 2가 반영된다.
6. 디버깅할 때 `used`의 참 개수, 답 길이, 첫 정점과 마지막 정점을 함께 확인한다.
7. 사전순 최소 회로가 필요할 때만 인접 목록 정렬이나 최소 힙을 고려한다. 정렬하면 `O(E log E)`가 추가된다.

## 변형

### 시작점과 끝점이 다른 무방향 오일러 경로

홀수 차수 정점이 정확히 2개여야 하며 그중 하나에서 시작해 다른 하나에서 끝난다. 홀수 차수가 0개면 기존
오일러 회로 조건이다. 연결 조건과 간선 ID 처리는 같다.

### 방향 그래프

회로는 간선이 있는 모든 관련 정점에서 `in_degree == out_degree`여야 한다. 시작점에서 실제 간선을 모두
소비했는지는 같은 `route.size()==E+1` 검증으로 확인할 수 있다. 시작·끝이 다른 경로라면 시작점은
`out=in+1`, 끝점은 `in=out+1`, 나머지는 같아야 한다.

### 사전순 회로

각 정점의 인접 간선을 원하는 순서로 정렬하고 그 순서에 맞춰 커서를 진행한다. 단순히 지역적으로 가장 작은
이웃을 선택해도 Hierholzer의 회로 존재성은 유지되지만, 문제의 “전체 출력 사전순 최소” 정의와 시작점 정책을
별도로 증명해야 한다. 정렬 비용도 포함한다.

### De Bruijn 수열

길이 `k-1` 문자열을 정점, 길이 `k` 문자열을 방향 간선으로 보면 모든 간선을 한 번씩 지나는 오일러 회로가
De Bruijn 수열을 만든다. 같은 Hierholzer 골격을 문자열 상태 그래프에 적용한다.

## 오늘 문제와의 연결

[`../2026-09-04/icpc_problem.cpp`](../2026-09-04/icpc_problem.cpp)는 CSES 1691 Mail Delivery를 반복형
Hierholzer로 해결한다.

- 우체국이 있는 정점 `1`을 스택의 유일한 시작점으로 고정한다.
- 입력 간선 번호를 `IncidentEdge::id`로 양쪽 인접 항목에 공유한다.
- `used[id]`로 모든 무방향 거리를 정확히 한 번만 선택한다.
- 모든 `adjacency[v].size()`가 짝수인지 먼저 검사한다.
- `next_incident[v]` 커서로 각 인접 항목을 한 번만 검사한다.
- 재귀 대신 `vertex_stack`을 사용해 `M=200,000`에서도 호출 스택 한도를 피한다.
- `reversed_route.size() == M+1`로 정점 1과 분리되어 남은 간선을 검출한다.
- `std::reverse` 없이 역인덱스로 출력해 추가 표준 알고리즘 심볼과 헤더를 만들지 않는다.

## 직접 해보기와 검증 질문

1. 삼각형 `1-2-3-1`에서 스택과 역순 경로가 매 단계 어떻게 바뀌는지 적는다.
2. 정점 1의 삼각형과 정점 4의 삼각형이 분리된 입력에서 차수 검사는 통과하지만 경로 크기 검사가 실패함을 보인다.
3. 두 정점 사이에 평행 간선 두 개가 있다고 가정하고, 같은 끝점 쌍 대신 edge id가 필요한 이유를 설명한다.
4. `used[id] = true`를 스택에서 정점을 꺼낼 때까지 미루면 어떤 중복 선택이 가능한지 반례를 만든다.
5. `cursor[v]` 없이 매번 인접 목록 처음부터 검색할 때 별 모양 멀티그래프에서 검사 횟수가 어떻게 증가하는지 계산한다.
6. 방향 그래프의 오일러 경로 조건으로 코드를 바꿀 때 차수 검사와 시작점 선택이 어떻게 달라지는지 설명한다.
