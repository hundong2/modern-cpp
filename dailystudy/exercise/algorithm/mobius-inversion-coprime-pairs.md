# 뫼비우스 반전으로 서로소 쌍 세기

## 정의와 적용 조건

뫼비우스 함수 `μ(d)`는 `μ(1)=1`, 서로 다른 소인수 `k`개의 곱이면 `(-1)^k`, 어떤 소수의 제곱으로 나누어떨어지면 `0`이다. 핵심 항등식은 `Σ_{d|g} μ(d) = [g=1]`이다. 여기서 대괄호는 조건이 참이면 1, 아니면 0인 지시 함수다. 두 수의 최대공약수가 1인지 일일이 계산할 때보다, 값 상한 `M`이 적당하고 같은 입력 값이 반복될 수 있는 대량의 **무순서 위치 쌍**을 한꺼번에 세는 데 유리하다.

입력이 모두 양의 정수이고 최대값 `M` 크기의 빈도 배열을 둘 수 있어야 한다. 음수·0이 포함되면 배수 열거와 최대공약수 정의를 별도로 정리해야 하며 아래 구현을 그대로 적용할 수 없다.

## 핵심 아이디어와 불변식

`frequency[x]`를 입력 값 `x`의 등장 횟수라 하고, `count[d] = Σ_{k: d|k} frequency[k]`로 둔다. `C(count[d],2)`는 두 값이 모두 `d`로 나누어떨어지는 서로 다른 위치 쌍의 수다. 그러면

```text
answer = Σ_{1≤i<j≤n} [gcd(x_i,x_j)=1]
       = Σ_{d=1..M} μ(d) · C(count[d],2).
```

각 위치 쌍은 자기 최대공약수의 모든 약수 `d`에 한 번씩 기여하고, 그 계수 합이 최대공약수 1일 때만 1이다. 입력 값이 같아도 **위치가 다르면 쌍**이라는 점이 `frequency`와 조합식에 반영된다. `count[1]=n`이며 `μ(d)=0`인 약수의 항은 버려도 결과가 같다.

뫼비우스 값을 만드는 선형 체의 불변식은 `smallest_prime[x]`가 `x`의 최소 소인수이고, 각 합성수 `x*p`는 `p≤smallest_prime[x]` 규칙 아래 정확히 한 번 생성된다는 것이다. `p|x`이면 `p²|x*p`라 `μ(x*p)=0`, 아니면 `μ(x*p)=-μ(x)`다.

## 단계별 절차

1. 입력을 읽으며 `frequency[x]`를 증가시키고 실제 최댓값 `M`을 찾는다.
2. `μ(1)=1`로 두고 최소 소인수 선형 체로 `μ(2..M)`을 계산한다.
3. 각 `d=1..M`에서 `μ(d)=0`이면 건너뛰고, `d,2d,3d,...≤M`의 빈도 합을 구한다.
4. `μ(d)·count[d]·(count[d]-1)/2`를 64비트 답에 더한다.
5. 답 하나를 출력한다.

## 의사코드와 C++ 뼈대

```text
frequency[1..M] ← 0
for each x in input: frequency[x]++
μ(1) ← 1
for x from 2 to M:                       // 최소 소인수 선형 체
    if smallest_prime[x] = 0:
        smallest_prime[x] ← x; primes.push(x); μ(x) ← -1
    for p in primes while p ≤ smallest_prime[x] and x ≤ M/p:
        smallest_prime[x*p] ← p
        if x mod p = 0: μ(x*p) ← 0; break
        μ(x*p) ← -μ(x)
answer ← 0 as 64-bit integer
for d from 1 to M:
    if μ(d) = 0: continue
    count ← sum of frequency[d], frequency[2d], ...
    answer ← answer + μ(d) * count * (count-1) / 2
```

다음 C++ 함수는 배수 집계와 반전의 핵심 뼈대다. `frequency`와 `mobius`는 길이 `max_value+1` 이상인 배열이고, `mobius`는 앞 절차로 계산된 상태여야 한다. 포인터는 저장하지 않고 함수 실행 중에만 빌린다.

```cpp
// 반환형 long long은 최대 약 50억인 답을 담는다. 두 포인터는 읽기 전용으로 빌린다.
long long count_coprime_pairs(const int* frequency,
                              const signed char* mobius,
                              int max_value) {
    long long answer{};
    // 각 d의 배수 빈도만 합쳐 count[d]를 만든다.
    for (int d{1}; d <= max_value; ++d) {
        if (mobius[d] == 0) continue;
        long long count{};
        for (int k{d}; k <= max_value; k += d) {
            count += frequency[k];
        }
        // count가 long long이라 첫 곱부터 64비트다.
        answer += static_cast<long long>(mobius[d]) * (count * (count - 1) / 2);
    }
    return answer;
}
```

## 정확성 근거

**보조정리 1 — 배수 빈도는 정확하다.** `d`의 양의 배수를 `d,2d,...≤M`으로 모두 훑고 해당 값의 등장 횟수를 더하므로 `count[d]`는 `d`로 나누어떨어지는 입력 위치의 수와 같다. 따라서 `C(count[d],2)`는 두 위치의 값이 모두 `d`의 배수인 쌍을 정확히 한 번 센다.

**보조정리 2 — 뫼비우스 지시 함수가 정확하다.** `g>1`의 서로 다른 소인수가 `r`개라면 제곱인수 없는 약수들의 뫼비우스 합은 `Σ_{k=0..r} C(r,k)(-1)^k=(1-1)^r=0`이다. `g=1`에는 약수 1만 있으므로 합이 1이다.

**보조정리 3 — 선형 체의 뫼비우스 값이 정확하다.** 소수 `p`는 `μ(p)=-1`로 기록된다. 합성수는 최소 소인수 `p`를 기준으로 유일하게 `x*p`로 만들어진다. `p|x`면 소수 제곱인수가 있어 0이고, `p∤x`면 새로운 소인수 하나가 추가되어 부호가 반대다. 크기에 대한 귀납으로 모든 값이 정의와 같다.

보조정리 1의 쌍을 모든 `d`에 대해 합치면 각 위치 쌍 `(i,j)`의 계수는 `Σ_{d|gcd(x_i,x_j)} μ(d)`다. 보조정리 2에 의해 서로소 쌍만 계수 1을 가지므로 최종 합이 정답이다.

## 시간·공간 복잡도

`M=max(x_i)`라 하자. 입력 빈도는 `O(n)`, 선형 체는 `O(M)`, 모든 `d`의 배수 순회는 `Σ_{d=1..M}⌊M/d⌋ = O(M log M)`이므로 총 `O(n+M log M)` 시간이다. `frequency`, 최소 소인수, 소수 목록, 뫼비우스 배열은 총 `O(M)` 공간이다. `μ(d)=0`을 건너뛰면 실제 순회는 줄지만 이 상한은 유지된다.

`n=100,000`이면 최대 쌍 수는 `C(n,2)=4,999,950,000`으로 32비트 부호 정수 범위를 넘는다. `count`와 답뿐 아니라 **조합식의 첫 곱셈 이전**에 64비트로 승격해야 한다. 최종 답은 `C(n,2)` 이하이나 반전 중 양·음의 부분합은 변할 수 있으므로 누적값도 64비트로 둔다.

## 흔한 실수

1. 값의 종류만 세어 중복 입력 위치를 버린다. 같은 값도 서로 다른 위치의 쌍을 만든다.
2. `count*(count-1)`을 `int`로 계산한 뒤 `long long`으로 대입한다. 대입 전에 이미 넘친다.
3. `μ(1)=1`을 누락한다. `d=1` 항은 모든 쌍을 세는 출발점이다.
4. `p|x`인데 `μ(x*p)=-μ(x)`로 계산한다. 이 경우 제곱인수가 있어 0이다.
5. `x*p`를 상한 검사 전에 계산한다. 큰 일반화 문제에서는 정수 범위가 넘칠 수 있으므로 `x≤M/p`를 검사한다.
6. `count[d]`를 서로 다른 값의 개수로 착각한다. 입력 **위치 수**여야 한다.
7. 답이 음수가 될 수 있다고 생각해 `unsigned`로 부분합을 계산한다. 중간 항은 음수이므로 부호 있는 64비트가 적합하다.

## 변형

- `gcd(x_i,x_j)=1`이 아닌 쌍은 전체 `C(n,2)`에서 답을 빼면 된다.
- 여러 질의에 대해 특정 gcd가 `g`인 쌍 수를 원하면 `count[d]`의 조합값을 배수 관계로 역순 누적해 `exact_gcd[g]`를 계산한다. 단일 서로소 질의보다 저장 공간이 든다.
- 입력 값 상한이 매우 크고 원소 수가 작으면 `M` 크기 배열 대신 각 수의 소인수 분해와 제곱인수 없는 약수 열거 또는 쌍별 gcd를 비교해야 한다. 어떤 쪽이 나은지는 `n`, 최댓값, 소인수 구조에 달렸다.
- 순서 있는 서로 다른 위치 쌍을 세는 문제라면 이 답을 두 배 한다. 같은 위치까지 허용하면 대각선 쌍의 조건을 따로 더한다.
