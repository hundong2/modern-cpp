# 상태와 전이로 푸는 동적 계획법

## 정의와 적용 조건

동적 계획법(DP)은 큰 문제의 최적해나 경우의 수를 서로 겹치는 작은 부분 문제의 답으로 만든다. 문제를 순서대로 처리할 수 있고, 미래에 필요한 과거 정보가 작은 **상태**로 요약되며, 같은 부분 문제를 반복 계산한다면 적합하다. 탐욕적으로 한 번 고른 선택을 되돌릴 수 없거나 모든 경로를 탐색해야 하는 문제와 달리, DP는 가능한 이전 상태의 답을 비교해 현재 상태의 답을 확정한다.

## 핵심 아이디어와 불변식

상태는 “지금까지 무엇을 처리했고, 마지막 선택이 무엇인가”를 정확히 표현해야 한다. `dp[i][s]`를 앞의 `i`개를 처리하고 상태가 `s`일 때의 최적값으로 정의하면 다음 불변식을 유지한다.

- 아직 처리하지 않은 입력의 세부 정보는 상태 전이에만 사용한다.
- `dp[i][s]`는 상태 `s`에 도달하는 모든 합법적 선택 중 최적값이다.
- 다음 표를 계산할 때 같은 단계의 갱신값을 이전 단계 값과 섞지 않는다.

## 단계별 절차

1. 답을 결정하는 최소한의 상태와 각 상태의 의미를 문장으로 쓴다.
2. 입력이 가장 작은 기저 상태를 초기화한다.
3. 현재 상태로 올 수 있는 모든 합법적인 이전 상태를 나열한다.
4. 최소화 문제라면 이전 최솟값에 현재 비용을 더해 점화식을 만든다.
5. 계산 순서가 의존성보다 뒤에 오도록 반복한다.
6. 마지막에 답이 될 수 있는 상태들을 다시 최소화한다.

## 의사 코드

```text
previous = first item's states
for each remaining item:
    for each current_state:
        current[current_state] = item_cost + min(valid previous states)
    previous = current
answer = min(previous states)
```

## 컴파일 가능한 C++ 뼈대

```cpp
#include <algorithm> // std::min
#include <array>     // std::array

using States = std::array<int, 3>; // 고정된 세 상태를 연속 저장한다.

States advance(const States& previous, const States& cost) {
    // const lvalue 참조는 배열을 복사하지 않고 읽으며 원본을 수정하지 않는다.
    return States{cost[0] + std::min(previous[1], previous[2]),
                  cost[1] + std::min(previous[0], previous[2]),
                  cost[2] + std::min(previous[0], previous[1])};
}

int main() {
    const States first{1, 50, 50};
    const States second{50, 1, 50};
    const States result{advance(first, second)}; // prvalue 결과로 result를 직접 초기화한다.
    return result[1] == 2 ? 0 : 1;
}
```

## 정확성 근거

기저 단계에서는 한 항목만 선택하므로 각 상태 값이 명백히 최적이다. `i-1` 단계의 모든 상태가 최적이라고 가정하자. `i` 단계의 특정 상태로 오는 모든 합법적 해는 반드시 허용된 이전 상태 하나를 거친다. 점화식은 그 모든 이전 상태의 최적값을 비교하고 현재 비용을 더하므로 해당 상태의 최적값을 얻는다. 수학적 귀납법으로 마지막 단계의 모든 상태가 최적이며, 그중 최소가 전체 최적해다.

## 시간·공간 복잡도

상태 수가 `S`이고 각 상태가 모든 이전 상태를 확인하면 시간은 `O(NS^2)`, 표 전체는 `O(NS)` 공간이다. 직전 단계만 필요하면 롤링 배열로 공간을 `O(S)`로 줄인다. RGB거리처럼 상태가 항상 3개면 각 전이는 상수 시간이므로 전체 시간 `O(N)`, DP 추가 공간 `O(1)`이다.

## 흔한 실수

- 상태 정의에 미래 판단에 필요한 정보를 빼서 잘못된 부분 문제를 합친다.
- 기저 상태를 무한대나 0으로 잘못 초기화한다.
- `previous`를 제자리 갱신해 새 값이 같은 단계의 다음 전이에 섞인다.
- 불가능한 상태를 0으로 두어 최솟값으로 선택되게 한다.
- 비용 합의 최댓값을 계산하지 않고 `int`를 사용해 오버플로한다.

## 변형

- 최댓값 DP는 `min` 대신 `max`와 적절한 불가능 상태를 사용한다.
- 경우의 수 DP는 가능한 이전 상태의 수를 더하고 필요하면 나머지 연산을 한다.
- 경로 복원은 각 상태에서 선택한 이전 상태를 별도 배열에 저장한다.
- 상태 전이가 DAG를 이루면 위상 순서 DP로 일반화할 수 있다.
- 상태 수가 크면 최솟값과 두 번째 최솟값, 누적합, 자료구조로 전이를 줄일 수 있다.

## 직접 해보기와 이해 검증

1. 집 두 개의 비용을 직접 정하고 세 상태를 손으로 계산한다.
2. 제자리 갱신 코드와 별도 `current` 코드가 다른 답을 내는 반례를 만든다.
3. “모든 완전한 해의 마지막 선택은 상태 중 하나다”라는 문장으로 최종 최소화가 완전함을 설명한다.
4. 상태 정의, 기저값, 점화식, 계산 순서, 정답 위치를 보지 않고 다시 작성해 컴파일한다.
