# 2026-08-21 이해 검증 체크포인트

코드를 보지 않고 답한 뒤 실제 선언과 주석을 다시 대조한다. 이름 번역이 아니라 각 식의 입력, 반환, 상태 변화, 복잡도와 수명을 말해야 통과다.

## Modern C++ 문법·아키텍처

1. `struct Header`와 `class HttpRequest`의 기본 접근 차이, `public`/`private`가 허용·금지하는 접근을 설명한다.
2. `explicit RequestBuilder(std::string url) : url_{std::move(url)} {}`에서 생성자에 반환형이 없는 이유, 값 매개변수, 멤버 초기화 목록의 실행 순서를 말한다.
3. `RequestBuilder builder = std::string{"/"};`과 `RequestBuilder builder{std::string{"/"}};` 중 무엇이 허용되는지 `explicit`과 연결한다.
4. `header(...) &`, `header(...) &&`, `build() const &`, `build() &&`의 끝 기호가 반환형이 아니라 어떤 수신 객체 조건인지 설명한다.
5. `reusable`, `RequestBuilder{...}`, `std::move(*this)`, `HttpRequest{...}`를 lvalue·prvalue·xvalue로 분류한다.
6. `reusable.header(...).build()`와 `RequestBuilder{...}.header(...).build()`에서 선택되는 오버로드를 순서대로 적는다.
7. lvalue build는 문자열/vector를 복사하고 rvalue build는 이동할 수 있는 이유를 각 멤버 식의 const와 값 범주로 설명한다.
8. `header(...) &&`가 반환하는 참조가 소유하지 않는 객체와 그 객체가 파괴되는 시점을 전체 식 기준으로 설명한다.
9. 반환 `HttpRequest` prvalue가 목적 객체를 초기화할 때 가능한 복사 생략과, 이동된 builder의 유효하지만 미지정인 상태를 구분한다.
10. `headers()` 반환 `const vector<Header>&`가 유효한 기간과 HttpRequest 파괴·이동·재대입 시 위험을 말한다.
11. builder가 “조립 중 변경 가능 상태”와 “완성된 소유 값”을 분리하는 실무상 장점을 불변식·테스트 관점에서 설명한다.
12. 이 코드가 로드·저장·비교·분기·함수 호출로 번역될 수 있지만 특정 명령을 단정할 수 없는 이유를 CPU·ABI·컴파일러·최적화와 연결한다.

## 표준 라이브러리 호출 계약

13. `headers_.push_back(Header{...})`의 정확한 수신 타입·호출 전 상태, 선택 오버로드, 인자 타입/값 범주/소유권, 반환형과 사용 여부를 말한다.
14. 위 push_back 성공 뒤 크기·용량·인자 상태, 상각 복잡도, 재할당이 포인터·참조·반복자에 미치는 영향과 예외 가능성을 설명한다.
15. `body_.append("\n")`의 수신 타입, 첫 인자의 배열→포인터 변환, 선택 오버로드, 반환 `string&`의 사용 여부와 길이 변화를 말한다.
16. `body_.append(text)`에서 text의 타입·값 범주·복사/소유권, 호출 뒤 text/body_, 복잡도·재할당·예외 보장을 설명한다.
17. `nodes.size()`와 `snapshot.headers().size()`의 인자 수, 반환형, 반환값 사용처, 상태 변화, 복잡도·예외를 비교한다.
18. `std::move(method_)`가 실제 이동을 하지 않는 이유, 반환 값 범주와 실제 소유권 이전을 수행하는 생성자를 설명한다.
19. `std::vector<TrieNode> nodes{TrieNode{}}`가 만드는 원소 수와 생성자 선택을 괄호 `vector<TrieNode>(1)`과 비교한다.
20. `std::array<int,10>{}`의 초기값, 저장 위치, 동적 할당 여부와 `operator[]`의 전제조건·반환 참조·범위 오류 계약을 설명한다.
21. 전화번호 범위 for가 암묵적으로 얻는 begin/end, 각 `digit`의 복사, 반복 중 number 상태와 반복자 유효성을 설명한다.
22. `std::cin >> number`의 수신 스트림, 입력 대상 lvalue, 반환형/무시 여부, 성공 뒤 문자열·입력 위치, 실패/할당 오류를 말한다.
23. `std::cout << (consistent ? "YES\n" : "NO\n")`의 입력 값, 반환 참조, 출력 상태 변화, 실패 표현과 버퍼 flush를 보장하지 않는 점을 설명한다.
24. `sync_with_stdio(false)`와 `cin.tie(nullptr)`의 각 수신/인자, 반환값을 버리는 이유, 호출 후 상태와 C stdio·대화형 출력 주의점을 말한다.

## 접두사 트라이와 BOJ 5052

25. 트라이 노드, 간선, terminal, 루트→현재 경로가 나타내는 접두사를 오늘 변수와 연결해 정의한다.
26. 삽입 반복 시작마다 유지하는 불변식을 쓰고 새 노드를 만든 뒤에도 유지되는 이유를 설명한다.
27. `nodes[current].terminal`을 문자 처리 전에 검사해야 `911`, `91125426` 순서의 충돌을 찾는 이유를 추적한다.
28. 모든 문자를 읽은 뒤 자식 배열을 검사해야 `12345`, `123` 순서의 충돌을 찾는 이유를 추적한다.
29. 끝 노드 terminal 재검사가 중복 `42`, `42`를 거르는 이유와 문제의 접두사 정의를 연결한다.
30. vector 재할당에도 정수 노드 인덱스가 안전하고 원소 포인터·참조는 위험한 이유를 주소와 논리 식별자 차이로 설명한다.
31. 인덱스 0을 자식 없음 sentinel과 루트에 함께 쓰면서도 충돌하지 않는 생성 규칙을 말한다.
32. 모든 번호 길이 합 `S`에서 시간 `O(S)`, 공간 `O(S)`가 되는 과정을 숫자 알파벳 크기 10과 함께 유도한다.
33. 고정 자식 배열과 map 기반 자식 표현을 조회 시간, 노드당 메모리, 희소 알파벳, 캐시 지역성 관점에서 비교한다.
34. 정렬 뒤 인접한 번호만 비교해도 되는 이유를 사전순에서 같은 접두사를 공유하는 문자열이 연속한다는 성질로 증명한다.
35. 공개 예제, 역순 접두사, 중복, 공통 접두사, 한 자리 접두사 CTest가 각각 어떤 결함을 잡는지 예상 출력과 함께 적는다.
36. 트라이가 자동 완성, 최대 XOR, Aho–Corasick으로 확장될 때 노드에 추가할 상태나 간선을 설명한다.
