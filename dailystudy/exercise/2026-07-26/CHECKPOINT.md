# 2026-07-26 초보자 검증 체크포인트

아래 단계는 “읽었다”가 아니라 “직접 설명하고 바꿀 수 있다”를 확인한다.

## 1단계 — 기초 문법 찾기

- [ ] 다섯 `#include`가 각각 왜 필요한지 코드의 사용 위치를 가리켜 설명한다.
- [ ] `int total{0};`에서 타입, 변수 이름, 중괄호 초기값을 구분한다.
- [ ] `checkout(const ItemList& items) const`에서 반환형, 매개변수, 참조, 두 `const`의 역할을 설명한다.
- [ ] `policy_.discount_for(total)`에서 객체, 함수 이름, 인자를 찾는다.
- [ ] `struct`와 `class`의 기본 접근 차이, `public:`과 `private:`의 효과를 말한다.

통과 기준: 위 항목을 코드 없이도 자기 말로 설명한다.

## 2단계 — 생성과 타입 계약

- [ ] 생성자에 반환형이 없음을 확인한다.
- [ ] `RatePolicy(int rate) : rate_{rate}`에서 생성자 매개변수와 멤버 초기화 목록을 구분한다.
- [ ] `explicit`이 `RatePolicy policy = 10;`을 막고 `RatePolicy policy{10};`은 허용하는 이유를 설명한다.
- [ ] `using ItemList = std::vector<Item>;`의 별칭과 두 템플릿 인자를 찾는다.
- [ ] `DiscountPolicy`가 검사하는 표현식과 검사하지 못하는 비즈니스 규칙을 하나씩 말한다.

통과 기준: `discount_for` 이름을 바꿔 컴파일 실패를 관찰하고 원상 복구한다.

## 3단계 — 값 범주와 수명

- [ ] 이름 있는 `items`가 lvalue인 이유를 설명한다.
- [ ] `Item{"펜", 1000}`이 prvalue인 이유를 설명한다.
- [ ] `std::move(policy)`가 xvalue를 만들 뿐 이동 자체는 아니라는 점을 설명한다.
- [ ] `const Item&`와 `Item&&`의 바인딩 대상을 비교한다.
- [ ] 목록의 소유자, 정책의 소유자, 싱크 포인터의 비소유 관계를 찾는다.
- [ ] 함수 반환에서 복사 생략이 가능한 식을 가리킨다.

통과 기준: 서비스가 싱크보다 오래 살면서 포인터를 사용하면 왜 위험한지 설명한다.

## 4단계 — 직접 수정

- [ ] `FixedPolicy`를 추가하고 `CheckoutService<FixedPolicy>`로 실행한다.
- [ ] 0 미만 또는 합계 초과 할인이 0으로 보정되는지 악성 정책으로 검증한다.
- [ ] `problem.cpp`에서 silver 등급은 5% 할인하도록 수정한다.
- [ ] 예상 결과를 먼저 종이에 계산한 뒤 프로그램 결과와 비교한다.

통과 기준: 수정본이 경고 없이 빌드되고 종료 코드가 0이다.

## 5단계 — 기계 실행과 아키텍처

- [ ] 합계 반복에서 로드·덧셈·저장·비교·조건 분기가 생길 수 있는 위치를 찾는다.
- [ ] 템플릿 정책 호출과 가상 `write` 호출의 차이를 설명한다.
- [ ] 실제 명령이 CPU, ABI, 컴파일러, 최적화 옵션에 따라 달라지는 이유를 말한다.
- [ ] 계산 정책과 출력 포트를 나눈 덕분에 독립적으로 바꿀 수 있는 것을 하나씩 든다.

최종 통과 기준: concept의 컴파일 시간 계약과 실행 시간 값 검증이 모두 필요한 이유를 3문장으로 설명한다.
