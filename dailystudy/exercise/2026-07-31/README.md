# 2026-07-31 — `std::numbers`와 단위 안전 도형 서비스

오늘은 C++20의 `std::numbers::pi_v<T>`로 원주율을 타입에 맞게 얻고, 원시 `double` 대신 `Radius` 값 객체로 유효성 규칙을 지킵니다. 아키텍처는 다음 역할로 나눕니다.

`Radius`(도메인 값) → `AreaPolicy`(계산 정책 포트) → `CircleAreaPolicy`(구현 어댑터) → `AreaService`(유스케이스)

서비스는 계산 공식과 출력 방법을 직접 알지 않습니다. `AreaPolicy` 인터페이스에 의존하므로 정책을 바꾸거나 테스트 대역을 넣기 쉽습니다. `std::unique_ptr`가 정책 객체를 단독 소유하고, 가상 함수 호출로 실제 구현을 선택합니다.

## 값 범주, 수명, 복사와 이동

이름이 있는 `radius`, `service`는 lvalue입니다. `Radius{2.0}`과 `std::make_unique<CircleAreaPolicy>()`의 결과는 prvalue입니다. `std::move(policy)`는 이름 있는 lvalue를 xvalue로 표현할 뿐이며, 실제 소유권 이동은 `unique_ptr`의 이동 생성자에서 일어납니다. 이동 뒤 원본 스마트 포인터는 비게 됩니다.

`Radius{2.0}`을 함수에 전달하면 `const Radius&`가 임시 객체에 바인딩되고, 그 임시 객체의 수명은 전체 함수 호출 식이 끝날 때까지 이어집니다. 서비스가 참조를 저장하지 않으므로 매달린 참조가 생기지 않습니다. `AreaResult{...}` 반환값은 prvalue이며 C++17 이후 보장되는 복사 생략으로 반환 목적지에 직접 만들어질 수 있습니다. `unique_ptr`는 복사가 금지되고 이동만 허용되어 단독 소유권을 코드로 강제합니다.

## 기계 실행 관점

개념적으로 반지름 멤버를 읽는 로드, 0과의 비교, 조건 분기, 곱셈, 결과 저장, 함수 호출이 일어납니다. `policy_->calculate(...)`는 동적 타입에 따라 구현을 고르는 가상 간접 호출이 될 수 있지만 컴파일러가 실제 타입을 증명하면 직접 호출처럼 최적화할 수도 있습니다. 실제 레지스터·메모리 접근·명령 선택·가상 호출 제거 여부는 CPU, ABI, 컴파일러와 최적화 옵션에 따라 달라지므로 특정 어셈블리 명령으로 단정하지 않습니다.
