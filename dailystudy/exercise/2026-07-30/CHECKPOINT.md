# 초보자 이해 검증

코드를 보지 않고 먼저 답하고, 그다음 코드에서 근거 줄을 찾으세요.

## 1단계 — 문법 읽기

- [ ] `<chrono>`, `<iostream>`, `<memory>`, `<utility>`를 각각 왜 포함했는지 말한다.
- [ ] `int`, `bool`, `std::chrono::milliseconds`가 각각 무엇을 표현하는지 말한다.
- [ ] `RetryPolicy policy{3, 2s};`가 중괄호 초기화인 이유를 말한다.
- [ ] `Decision decide(int failures) const`에서 반환형, 함수 이름, 매개변수, `const`의 뜻을 짚는다.
- [ ] 생성자에는 반환형이 없고, 생성자 매개변수와 멤버 초기화 목록은 서로 다른 역할임을 설명한다.
- [ ] `struct`의 기본 접근은 `public`, `class`의 기본 접근은 `private`임을 설명한다.
- [ ] `public:`과 `private:`가 외부에서 접근 가능한 범위를 어떻게 나누는지 말한다.
- [ ] `explicit`이 막는 암시적 변환과 `RetryService service{...};` 같은 올바른 직접 초기화를 구분한다.

## 2단계 — Modern C++와 아키텍처

- [ ] `using Duration = std::chrono::milliseconds;`가 새 타입이 아니라 타입 별칭임을 설명한다.
- [ ] `duration<Rep, Period>`의 두 템플릿 인자가 숫자 표현과 단위를 정함을 설명한다.
- [ ] `Clock`이 포트이고 `ManualClock`이 어댑터인 이유를 설명한다.
- [ ] 가짜 시계가 실제 대기 없는 빠르고 결정적인 테스트를 가능하게 하는 이유를 설명한다.
- [ ] `duration_cast`를 쓰는 이유와 `>=`, `+`, `&&`, `->`, `<<` 연산자의 역할을 각각 말한다.

## 3단계 — 값·수명·소유권

- [ ] 이름 있는 변수 하나를 lvalue, 중괄호로 만든 결과 하나를 prvalue로 지목한다.
- [ ] `std::move(clock)`이 xvalue 식이며 실제 이동은 이어지는 이동 생성에서 일어남을 설명한다.
- [ ] 이동 후 원래 `unique_ptr`이 비는 이유를 소유권과 연결한다.
- [ ] `const Clock&`가 소유하지 않는 참조이며 참조 대상의 수명이 더 길어야 함을 말한다.
- [ ] `Decision{...}` 반환에서 복사 생략이 가능한 이유를 설명한다.

## 4단계 — 직접 증명

- [ ] `2s`를 `2500ms`로 바꾸고 두 번째 판단의 결과를 예측한 뒤 실행해 확인한다.
- [ ] 최대 실패 횟수를 3에서 1로 바꾸고 어느 조건 분기가 선택되는지 확인한다.
- [ ] `clock_ptr`의 `const Clock*` 포인터를 만들어 null이 아님을 조건문으로 검사한다.
- [ ] 반복문을 3회에서 5회로 바꾸고 출력 횟수를 확인한다.
- [ ] CPU·ABI·컴파일러·최적화에 따라 실제 명령이 달라져 특정 어셈블리를 단정할 수 없다고 설명한다.

합격 기준: 체크만 하지 말고, 4단계 중 두 항목 이상을 실제로 수정·빌드·실행한 뒤 원상 복구합니다.
