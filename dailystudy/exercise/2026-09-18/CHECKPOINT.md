## C++ 기초 문법 확인

1. `#include <flat_map>`과 `<string>`은 각자 어떤 선언을 이 번역 단위에서 사용할 수 있게 하는가? 전이 포함에 기대면 왜 곤란한가?
2. `int count{}`와 `int count;`가 지역 변수일 때 차이를 말하고, `int x{3.5};`가 컴파일되지 않는 이유를 설명한다.
3. `struct`와 `class`의 기본 접근 수준, `public`/`private`의 경계, `explicit` 생성자의 목적을 자신의 말로 적는다.
4. `using Key = std::string;`에서 `Key`가 새 강한 타입인지 답하고, `std::flat_map<Key,int>`의 두 템플릿 인자가 각자 뜻하는 것을 적는다.
5. 생성자 `: key_{std::move(key)}`에서 실제 멤버 초기화 순서와 `std::move` 자체가 데이터를 옮기는지 설명한다.
6. `const T&`와 `const T*`가 각각 무엇을 빌리는가? nullptr·댕글링을 구별하고, `if`가 어떤 식의 값을 검사하는지 말한다.

## 알고리즘과 풀이 검증

1. `μ(1)=1`, 소수 `p`에 대해 `μ(p)=-1`, 제곱인수 `p²`를 가진 수의 `μ`가 0인 이유를 약수 합 항등식과 연결한다.
2. `cnt[d]`를 입력 원소의 *값*이 아닌 *인덱스 수*로 세는 이유를 `1 1`과 `2 2`로 검증한다.
3. `Σ_d μ(d) C(cnt[d],2)`에서 한 쌍 `(x_i,x_j)`의 계수를 직접 묶어 `gcd=1`일 때만 1임을 증명한다.
4. `n=100000`개가 모두 1이면 정답을 계산한다. `cnt*(cnt-1)` 연산 전에 왜 64비트로 승격해야 하는가?
5. `2 3 4 9`의 정답을 직접 세어 CTest 결과와 비교하고, 배수 루프를 `M`까지만 수행해도 되는 이유를 설명한다.
6. 작은 입력을 직접 전수 검사하는 느린 기준 풀이를 만들고 무작위 테스트로 빠른 풀이와 비교한다. `M`과 `n`에 따른 시간·공간 복잡도를 도출한다.
