# Modern C++ 표준 라이브러리 학습 지도

이 폴더는 날짜별 C++ 코드에 등장하는 표준 라이브러리 **타입, 함수, 함수 템플릿, 멤버 함수, 객체, 연산자, 용어**를 한곳에서 찾아볼 수 있게 관리한다. 코드 가까운 한글 주석은 “지금 이 줄이 하는 일”을 설명하고, 이 문서는 재사용 가능한 계약과 배경지식을 설명한다.

## 읽는 순서

1. 날짜별 README의 `오늘 사용한 표준 라이브러리` 표에서 심볼과 헤더를 확인한다.
2. 코드 바로 위 주석에서 현재 인자와 반환값이 프로그램 상태를 어떻게 바꾸는지 읽는다.
3. 이 폴더의 대표 문서에서 복잡도, 수명, 무효화, 오류 조건까지 확인한다.
4. [`by-date.md`](by-date.md)에서 기존 86개 C++ 파일이 사용하는 심볼을 날짜별로 다시 찾는다.
5. [`../tools/audit-standard-library-docs.ps1`](../tools/audit-standard-library-docs.ps1)로 문서에 등록되지 않은 심볼이 있는지 검사한다.

## 좋은 설명의 최소 계약

표준 라이브러리 항목을 처음 의미 있게 사용할 때는 다음 질문에 답한다. 모든 항목을 긴 문단으로 코드에 반복하지 않고, 현재 줄에 중요한 내용은 인접 주석에 두고 재사용 지식은 이 폴더에 둔다.

1. **정의 위치**: 어떤 헤더가 선언을 제공하는가?
2. **항목의 종류**: 타입, 함수, 함수 템플릿, 멤버 함수, 객체, 연산자 중 무엇인가?
3. **호출 계약**: 매개변수는 값/포인터/참조 중 무엇이며 무엇을 빌리는가 또는 소유하는가?
4. **반환값**: 값, 참조, 포인터, 반복자, 상태 코드 중 무엇이며 실패는 어떻게 표현하는가?
5. **전제조건과 사후조건**: 호출 전 무엇이 참이어야 하고 호출 후 무엇이 바뀌는가?
6. **복잡도**: 상수, 선형, 로그, 상각 상수 중 무엇인가?
7. **수명과 무효화**: 반환 뷰·참조·반복자가 언제 무효가 되는가? 재할당이 일어나는가?
8. **오류와 예외**: 예외, `error_code`, 빈 상태, 종료 중 어느 방식인가?
9. **현재 코드의 이유**: 가능한 다른 도구 대신 이것을 선택한 이유는 무엇인가?
10. **기계 실행 관점**: 필요한 경우 로드·저장·비교·분기·간접 호출 가능성을 설명하되 실제 명령은 CPU·ABI·컴파일러·최적화에 따라 달라짐을 밝힌다.

특히 함수 호출은 타입 설명과 분리해 다음 순서로 읽는다.

1. `receiver.member(arg1, arg2)`에서 `receiver`의 정확한 타입과 호출 전 상태를 찾는다.
2. 선택된 오버로드의 대표 시그니처를 적고 템플릿 인자와 기본 인자를 확인한다.
3. `arg1`, `arg2`를 위치별로 나누어 타입, 값 범주, 복사·이동·참조·소유권, 허용·금지 값을 설명한다.
4. 반환형과 반환값이 나타내는 시점을 설명하고, 호출부가 저장·검사·무시하는지 확인한다.
5. 호출 뒤 수신 객체와 각 인자의 값·크기·용량·소유권·수명이 바뀌는지 또는 그대로인지 말한다.

예를 들어 `atomic.load(memory_order)`의 `memory_order`는 읽을 데이터가 아니라 순서 규칙이고, 출력은 관찰한 원자 값이며 수신 원자 객체는 바뀌지 않는다. 이처럼 **입력값, 제어용 옵션, 출력값을 서로 구분**하지 않은 설명은 완료로 보지 않는다.

## 코드 주석과 공용 문서의 역할 분담

다음처럼 “제공한다”로 끝나는 주석만으로는 부족하다.

```cpp
// vector를 제공한다.
#include <vector>
```

헤더 주석은 이 파일에서 실제로 쓰는 기능을 말하고, 호출 주석은 상태 변화와 계약을 말해야 한다.

```cpp
// <vector>는 연속 메모리를 소유하는 std::vector와 size/push_back 반복자 API를 선언한다.
#include <vector>

// 호출 계약: values는 vector<T> 수신 객체이고 push_back(const T&) 또는 push_back(T&&) 중 인자에 맞는 오버로드를 고른다.
// 입력 next는 새 원소의 원본이고 반환형은 void다. 성공하면 size가 1 증가하며, 용량 부족 재할당 시 기존 관찰자가 무효화된다.
values.push_back(next);
```

`std::vector`의 일반 계약, 상각 `O(1)` 복잡도, `reserve`와 재할당 규칙은 [`containers-and-views.md`](containers-and-views.md)에 한 번만 자세히 둔다.

## 현재 자료에 적용하는 완료 기준

- C++ 파일에서 추출한 모든 `std::...` 심볼은 [`symbol-index.md`](symbol-index.md) 또는 세부 문서에 정확한 표기로 존재한다.
- `#include <...>` 주석은 헤더 이름만 되풀이하지 않고 현재 파일에서 쓰는 선언을 구체적으로 말한다.
- `push_back`, `emplace`, `reserve`, `size`, `empty`, `front`, `begin/end`, `find`, `load/store`, `lock`, `value/error`처럼 `std::`가 없는 멤버 함수도 첫 의미 있는 호출에서 설명한다.
- 날짜별 README는 그날의 핵심 표준 라이브러리 5~12개를 헤더·종류·역할·주의점과 함께 표로 연결한다.
- CHECKPOINT에는 반환형, 실패 표현, 복잡도, 수명/무효화 중 최소 두 가지를 직접 설명하는 문제가 있다.
- 설명을 추가한 뒤 컴파일·실행·CTest와 표준 라이브러리 문서 감사를 모두 통과해야 한다.

## 직접 검증

1. 임의의 `std::` 호출을 하나 고르고 위 열 가지 질문에 자료 없이 답한다.
2. 멤버 함수 호출 하나를 고르고 호출 전후 컨테이너 크기·용량·반복자 유효성을 적는다.
3. 반환값을 무시하면 안 되는 함수와 무시해도 되는 함수의 예를 각각 찾는다.
4. 같은 문제를 해결하는 두 표준 도구의 소유권·복잡도·오류 표현 차이를 비교한다.
