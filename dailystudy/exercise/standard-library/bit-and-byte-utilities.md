# 비트, 바이트, 객체 표현 유틸리티

이 문서는 실질적으로 같은 표준 기능을 날짜별로 반복하지 않고 `<bit>`, `<cstdint>`, `<cstddef>`의 저수준 표현 도구를 한곳에서 설명한다. 객체 표현은 전송 프로토콜 자체가 아니므로 필드 폭·순서·버전·유효성 검사는 별도 경계가 책임져야 한다.

## `std::bit_cast<To>(from)` — `<bit>` 함수 템플릿

- 대표 형태: `template<class To, class From> constexpr To bit_cast(const From& from) noexcept;`
- `To`는 호출부가 명시하는 목적 타입이고 `From`은 인자에서 추론된다.
- `sizeof(To) == sizeof(From)`이고 두 타입이 trivially copyable이어야 한다. 조건을 만족하지 않으면 호출 후보가 되지 않는다.
- `from`은 `const From&`로 읽을 뿐 수정하거나 소유하지 않는다. 반환형은 새 `To` 값이며 원본과 독립적으로 수명을 가진다.
- 같은 크기의 객체 표현 비트를 복사한다. 엔디언 변환, 구조체 패딩 제거, 직렬화 버전 관리는 하지 않는다.
- 올바른 별칭 규칙을 깨는 포인터 `reinterpret_cast` 역참조 대신 값 복사에 쓸 수 있다.
- 고정 크기 복사라 시간·추가 공간은 `O(sizeof(To))`이고 오늘의 4바이트 타입에서는 상수다. 동적 할당과 표준 예외는 없다.
- 대상 타입에서 값이 없는 비트 표현이나 수명 밖의 하위 객체를 읽는 상황은 별도 규칙을 확인해야 한다. 임의 바이트를 어떤 타입으로든 바꿔도 안전하다는 허가가 아니다.

## `std::byteswap(value)` — `<bit>` 함수 템플릿(C++23)

- 대표 형태: `template<class T> constexpr T byteswap(T value) noexcept;`
- `T`는 padding bit가 없는 정수 타입이어야 한다. `bool`, 부동소수점, 포인터, 임의 구조체에 쓰는 도구가 아니다.
- 값 매개변수를 복사해 바이트 순서를 반대로 배치한 같은 타입 prvalue를 반환한다. 호출자의 인자는 변하지 않는다.
- 동적 할당과 예외가 없고 고정 폭 정수에서는 `O(sizeof(T))`, 오늘의 32비트 값에서는 상수 시간·공간이다.
- 실제로 단일 바이트 교환 명령, 시프트 조합, 컴파일 시간 계산이 될지는 CPU와 최적화에 달려 있다.

## `std::popcount(x)` — `<bit>` 함수 템플릿(C++20)

### 종류, 선언, 타입 제약

- **항목 종류·헤더**: `<bit>`가 선언하는 `std` 네임스페이스의 `constexpr` 자유 함수 템플릿이다. 멤버 함수나 상태를 가진 함수 객체가 아니다.
- **대표 시그니처**: `template<class T> constexpr int popcount(T x) noexcept;`이다. 실제 호출에서는 인자 타입으로 `T`가 추론된 함수 템플릿 특수화가 선택된다.
- **정확한 참여 조건**: `T`가 `unsigned char`, `unsigned short`, `unsigned int`, `unsigned long`, `unsigned long long` 또는 구현이 제공하는 확장 **부호 없는 정수 타입**일 때만 오버로드 결정에 참여한다. `bool`, 부호 있는 정수, 평범한 `char`, 부동소수점, 포인터와 열거형은 허용되지 않는다. `std::uint64_t`가 존재한다면 위 부호 없는 정수 타입 중 정확히 64비트인 타입의 별칭이므로 오늘 호출의 조건을 만족한다.

### 엄격한 호출 계약

1. **수신 객체와 호출 전 상태**: 자유 함수라 수신 객체는 없다. `std::popcount(word)`에서 호출 전에 `word`는 수명이 유효한 `const std::uint64_t` 또는 읽을 수 있는 `std::uint64_t` 객체여야 한다. 표현 가능한 모든 값(0과 최댓값 포함)이 유효하다.
2. **선택 시그니처·템플릿 인자**: 오늘 세 코드 파일의 호출은 `T = std::uint64_t`인 `constexpr int popcount(std::uint64_t) noexcept` 특수화를 선택한다. 여기서 `std::uint64_t`는 별칭이므로 실제 구현의 대응 부호 없는 정수 타입과 같은 타입이다.
3. **인자 식·값 범주·소유권**: `word`나 `bits_` 같은 lvalue 식은 lvalue-to-rvalue 변환으로 값을 읽어 값 매개변수 `x`에 복사한다. `x`는 읽기 전용 계산 재료이며 함수가 호출자 객체의 포인터·참조를 보관하거나 저장소 소유권을 넘겨받지 않는다. 부호 없는 prvalue도 그대로 전달할 수 있다.
4. **반환형·값·사용**: 반환형은 `int`이고, 반환 prvalue는 `x`의 값 표현에서 1인 비트의 개수, 즉 `[0, std::numeric_limits<T>::digits]` 범위다. `main.cpp`와 `problem.cpp`는 각각 권한 mask의 `count()` 결과로 사용하고, `icpc_problem.cpp`는 각 64비트 워드의 결과를 행별 도달 정점 수에 합산한다.
5. **호출 뒤 상태**: 호출자의 `word`/`bits_`와 이를 소유한 객체는 바뀌지 않는다. 값 매개변수 `x`의 수명만 함수 반환 때 끝나고 반환 `int` 값은 원본과 독립적이다. 반복자·포인터·참조 무효화나 컨테이너 원소 수명 변화도 없다.
6. **전제·후조건·비용·오류·스레드**: 유효한 부호 없는 `T` 값이면 후조건은 정확한 1비트 수 반환이다. 표준은 복잡도 상한, 특정 CPU 명령, 고정된 단계 수를 따로 보장하지 않는다. 단순한 휴대용 구현을 설명할 때는 비트 폭에 선형인 `O(std::numeric_limits<T>::digits)` 비용 모델을 쓸 수 있지만 이는 규범적 계약이 아니다. 오늘의 고정 `std::uint64_t` 호출은 입력 크기가 늘지 않는 한 프로그램 분석에서 상수 비용 한 단위로 센다. 추가 동적 할당과 표준 예외가 없으며 `noexcept`다. 유효한 호출 자체에는 오류값이나 미정의 동작이 없다. 조건을 만족하지 않는 타입은 런타임 오류가 아니라 일치하는 오버로드가 없어 컴파일되지 않는다. 함수는 공유 상태를 쓰지 않아 독립 값 호출끼리는 병행 가능하지만, 인자 평가와 동시에 같은 원본 객체를 동기화 없이 수정하면 값 복사 단계에서 일반 데이터 경쟁이 생길 수 있다.

### 기계 실행과 2026-10-23 코드의 역할

- 구현은 대상 CPU가 지원하면 population-count 명령을 사용할 수 있고, 여러 비트 연산이나 루프로 낮출 수도 있으며, 상수 인자는 컴파일 시간에 접을 수도 있다. 어느 형태인지는 CPU, ABI, 컴파일러, 표준 라이브러리와 최적화 옵션에 따라 달라지므로 소스만 보고 단일 명령이라고 단정하지 않는다.
- `2026-10-23/main.cpp`의 `CapabilitySet::count()`는 `BitWord = std::uint64_t`인 값 타입 내부 비트 저장소 `bits_`를 읽어 켜진 권한 수를 반환한다. 값 복사 호출이라 캡슐화한 권한 집합의 소유권과 상태는 유지된다.
- `2026-10-23/problem.cpp`의 `PermissionMask::count()`는 세 권한 bit를 직접 켜고 세는 작은 실습으로, 반환 `int`와 원본 mask의 불변 상태를 눈으로 확인하게 한다.
- `2026-10-23/icpc_problem.cpp`의 CSES 2138 풀이는 DAG의 역위상 순서에서 `reach[u] = {u} ∪ ⋃(u→v) reach[v]`를 64비트 워드 OR로 완성한 뒤, 한 행의 각 `std::uint64_t word`에 `std::popcount(word)`를 적용해 자기 자신을 포함한 서로 다른 도달 정점 수를 센다. 마지막 워드의 사용하지 않는 상위 비트는 처음부터 0이고 유효 정점 비트만 OR한다는 불변식이 있어 별도의 꼬리 마스크 없이도 합이 정확하다. 알고리즘 설명은 [`../algorithm/dag-transitive-closure-word-bitsets.md`](../algorithm/dag-transitive-closure-word-bitsets.md)를 참고한다.

### 최소 컴파일 예제

```cpp
#include <bit>
#include <cstdint>

int main() {
    // 세 비트가 켜진 64비트 부호 없는 값을 소유한다.
    const std::uint64_t permissions{0b101001U};
    // lvalue 값을 복사해 읽고 독립적인 int 결과를 받는다. permissions는 변하지 않는다.
    const int enabled{std::popcount(permissions)};
    static_assert(std::popcount(std::uint64_t{0b101001U}) == 3);
    return enabled == 3 ? 0 : 1;
}
```

### 흔한 실수

1. `std::popcount(-1)`처럼 부호 있는 값을 직접 넘길 수 있다고 생각하지 않는다. 이 식은 지원 타입 제약을 만족하지 않는다.
2. 음수를 무작정 unsigned로 변환하면 modulo 변환된 비트 패턴의 1을 세게 된다. 컴파일된다는 사실이 원래 수학적 의도까지 보장하지 않는다.
3. 강한 enum은 기저 타입이 unsigned여도 enum 자체가 부호 없는 정수 타입은 아니다. 유효성 검사 뒤 명시적으로 기저 unsigned 타입으로 바꿔야 한다.
4. 결과가 입력 타입과 같은 unsigned라고 가정하지 않는다. 반환형은 `int`이며 여러 워드 결과를 합칠 누산 타입은 전체 최대 합을 표현하도록 별도로 고른다.
5. 동적 폭 비트셋 전체를 한 번에 받는 함수라고 오해하지 않는다. 각 부호 없는 정수 워드마다 호출하고 결과를 합산해야 한다.
6. 마지막 워드의 유효 범위 밖 패딩 비트를 1로 둔 채 세지 않는다. 오늘 풀이는 그 비트를 한 번도 설정하지 않는 불변식으로 이를 막는다.

## `std::endian` — `<bit>` 열거형

- `std::endian::little`, `std::endian::big`은 알려진 작은/큰 바이트 순서를 나타낸다.
- `std::endian::native`는 실행 구현의 스칼라 바이트 순서를 나타내는 컴파일 시간 값이다.
- native가 little 또는 big과 같지 않은 혼합 엔디언 구현도 표준상 가능하다. 지원하지 않으면 오늘 코드처럼 `static_assert`로 명시적으로 거부한다.
- 열거자 비교는 값을 읽을 뿐 전역 상태나 객체를 바꾸지 않고 할당·예외가 없다.
- 네트워크 바이트 순서는 관례상 big-endian이지만 파일/프로토콜 명세가 정한 순서를 항상 우선한다.

## `std::int64_t`, `std::uint16_t`, `std::uint32_t`, `std::uint64_t`, `std::uintmax_t`, `std::byte`, `std::size_t`, `std::ptrdiff_t`

### `std::int64_t` — `<cstdint>` 타입 별칭

- 구현이 정확히 64비트인 부호 있는 정수 타입을 제공할 때 존재한다. 오늘 볼록 껍질 코드는 좌표와 외적의 음수·0·양수 부호를 모두 보존해야 하므로 이 타입을 쓴다.
- 표현 범위는 `-2^63`부터 `2^63-1`까지다. CSES 2195의 좌표 차는 최대 `2*10^9`, 외적은 최대 절댓값 `8*10^18`이라 범위 안이지만, 더 큰 좌표 문제에는 더 넓은 중간 타입이 필요하다.
- 타입 별칭 자체에는 함수 호출, 수신자, 매개변수, 반환값, 할당·무효화·수명·예외 또는 스레드 상태 변화가 없다. 해당 타입 객체의 연산 복잡도는 고정 폭에서 상수지만 실제 명령은 구현과 CPU에 달려 있다.
- 부호 있는 산술이 표현 범위를 넘으면 modulo wrap이 보장되지 않고 미정의 동작이다. 곱셈 뒤 좁히는 것이 아니라 곱셈 **전에** 충분히 넓은 타입을 선택해야 한다.

### `std::uint16_t`, `std::uint32_t` — `<cstdint>` 타입 별칭

- `std::uint16_t`와 `std::uint32_t`는 구현이 정확히 16비트·32비트인 부호 없는 정수 타입을 제공할 때 각각 존재한다. 2026-10-14 자료는 명시 기저 타입이 `uint16_t`인 강한 enum을 같은 타입 wire field로 변환해 폭의 우연한 변경을 막는다.
- 모듈 간 메모리 ABI를 무조건 보장하는 것이 아니라 수치 폭을 표현한다. 직렬화에는 바이트 순서와 필드 배치 계약이 추가로 필요하다.
- 부호 없는 산술은 2의 비트 수 제곱을 법으로 순환한다. 범위 검증 없이 오버플로를 오류 탐지로 사용하지 않는다.
- 타입 별칭 자체에는 수신자·매개변수·반환값이 없고 객체 수명이나 소유권을 만들지 않는다. 값 초기화·비교·비트 연산은 고정 폭에서 상수 시간·상수 공간이고 할당·참조 무효화·표준 예외가 없다. 같은 객체를 한 스레드가 쓰는 동안 다른 스레드가 무동기 접근하면 일반 데이터 경쟁 규칙을 따른다.

### `std::uint64_t`, `std::uintmax_t` — `<cstdint>` 타입 별칭

- `std::uint64_t`는 구현이 정확히 64비트인 부호 없는 정수 타입을 제공할 때 존재하며 큰 카운터·거리의 수치 폭을 명시한다.
- `std::uintmax_t`는 구현이 제공하는 부호 없는 정수 타입 가운데 가장 넓은 타입이다. 파일 크기처럼 API가 이 타입을 반환하면 더 좁은 타입으로 바꾸기 전에 범위를 검사한다.
- 두 타입 모두 부호 없는 산술의 modulo 규칙을 따르므로 wraparound가 오류 신호라는 뜻은 아니다.

### `std::byte` — `<cstddef>` enum class

- 원시 저장 단위를 정수 값과 구분한다. 암시적으로 정수로 변환되지 않아 바이트에 우연히 산술하는 일을 줄인다.
- 비트 연산은 지원하지만 숫자로 읽으려면 `std::to_integer` 같은 명시적 변환이 필요하다.
- `array<byte, N>`은 바이트를 값으로 소유한다. 컨테이너 수명과 함께 원소 수명도 끝난다.

### `std::size_t` — `<cstddef>` 타입 별칭

- **항목 종류·헤더·현재 역할**: `<cstddef>`가 제공하는 구현 정의 부호 없는 정수 타입 별칭이며 `sizeof` 결과와 객체 크기를 표현할 수 있다. 2026-09-25 CSES 1628 풀이는 vector 인덱스 `first/last/position/index`, 절반 폭 `width`, 부분집합 수 `subset_count`에 쓰고 `std::size_t{1} << width`로 최대 `2^20`개 상태 수를 계산한다.
- **호출·수신 객체·매개변수**: 타입 별칭 자체는 함수/멤버/객체가 아니므로 호출 수신자, 함수 시그니처, 매개변수, 선택 overload와 소유권 이전은 해당 없음이다. `std::size_t{1}`은 값 1의 prvalue를 직접 목록 초기화하고 내장 `operator<<`는 그 값과 `width` 값을 읽을 뿐 어느 객체도 소유하지 않는다.
- **결과와 사후 상태**: 내장 shift 전에 integral promotion이 적용되므로 좁은 `std::size_t`라면 왼쪽 피연산자 타입이 `int` 또는 `unsigned int`로 바뀔 수 있다. 정의된 범위에서 값은 `2^width`이고 오늘 코드는 결과를 명시적으로 `std::size_t`로 변환해 `subset_count`에 저장한다. `width`, vector와 기존 인덱스는 바뀌지 않는다. 타입 별칭 선언 자체에는 반환값이나 상태 변화가 없다.
- **복잡도·할당·무효화·수명**: 고정 폭 정수 초기화·비교·shift는 추상 기계에서 상수 시간·상수 공간이고 동적 할당, 컨테이너 관찰자 무효화, 원소 수명 변화가 없다. 지역 `std::size_t` 객체는 각 블록 자동 수명을 따르며 별칭 이름에는 별도 수명이 없다.
- **전제조건·오류·미정의 동작**: 왼쪽 shift count는 음수가 아니고 **승격된** 왼쪽 피연산자의 값 비트 수보다 작아야 하며, 그렇지 않으면 미정의 동작이다. 오늘 코드는 `width<=20` 불변식과 `static_cast<std::size_t>(1'048'576ULL) == 1'048'576ULL` compile-time guard로 `std::size_t`가 `2^20`까지 표현함을 직접 확인한다. 단순히 `std::size_t{1} << 20`만 검사하면 좁은 `size_t`가 `int`로 승격되어 잘못 통과할 수 있다. 음수 `int`를 unsigned로 바꾸면 큰 값이 되고 unsigned 산술은 modulo로 순환하므로 wrap을 오류 검출로 오해하면 안 된다. 타입 별칭 자체는 예외를 던지거나 오류값을 만들지 않는다.
- **스레드·기계 실행 관점**: 독립된 값 계산에는 공유 상태와 자체 동기화가 없다. 같은 `std::size_t` 객체를 한 실행 흐름이 쓰는 동안 다른 흐름이 동기화 없이 읽거나 쓰면 일반 데이터 경쟁 규칙을 따른다. 실제 레지스터 폭과 shift 명령·상수 접기는 CPU, ABI, 컴파일러와 최적화 옵션에 따라 달라진다.

### `std::ptrdiff_t` — `<cstddef>` 타입 별칭

- 같은 배열 안 두 원소의 인덱스 차이와 두 포인터의 뺄셈 결과를 표현하도록 구현이 정하는 부호 있는 정수 타입이다.
- 원시 포인터 반복자의 `difference_type`은 `std::ptrdiff_t`지만, 일반 반복자는 `std::iterator_traits<I>::difference_type`을 사용하므로 모든 반복자 차이 타입이 `ptrdiff_t`라고 단정하지 않는다. 서로 무관한 배열의 포인터를 빼는 것은 허용되지 않고 표현 범위를 넘는 결과도 안전한 거리 계산이 아니다.

## 와이어 경계의 전제조건과 후조건

- 호출 전: 필드 폭과 허용 범위, 프로토콜 바이트 순서, 버전을 알아야 한다.
- 호출 후: 반환 바이트 값은 원본 객체와 독립적이어야 하며 원본 소유권과 수명은 유지된다.
- 고정 `array`는 재할당하지 않으므로 원소 포인터·참조는 배열 수명 동안 유지되지만, 범위 밖 `operator[]`는 미정의 동작이다.
- 저수준 함수 자체는 오류 코드를 만들지 않는다. 잘못된 길이·버전·필드 값은 코덱 계층이 `expected`, 오류 코드 등으로 표현해야 한다.
- 공유 가변 객체를 동시에 읽고 쓰는 스레드 안전은 제공하지 않는다. 독립된 값 객체끼리의 변환만 데이터 경쟁이 없다.

## 최소 실행 예제

```cpp
#include <array>
#include <bit>
#include <cstddef>
#include <cstdint>

int main() {
    static_assert(std::endian::native == std::endian::little ||
                  std::endian::native == std::endian::big);
    const std::uint32_t host{0x01020304U};
    const std::uint32_t network{
        std::endian::native == std::endian::little ? std::byteswap(host) : host};
    const auto bytes{std::bit_cast<std::array<std::byte, 4>>(network)};
    const auto copied{std::bit_cast<std::uint32_t>(bytes)};
    const std::uint32_t restored{
        std::endian::native == std::endian::little ? std::byteswap(copied) : copied};
    return restored == host ? 0 : 1;
}
```

## 흔한 실수와 직접 검증

1. `bit_cast`가 엔디언까지 바꾼다고 오해하지 않는다.
2. 패딩이 있을 수 있는 구조체 전체를 안정된 파일 형식이라고 가정하지 않는다.
3. `reinterpret_cast<T*>(bytes.data())` 역참조의 정렬·별칭·수명 문제를 설명한다.
4. 0x01020304를 little/big-endian 메모리에 놓았을 때 주소 증가 순서의 바이트를 적는다.
5. 16비트와 64비트 필드용 코드를 만들고 왕복 값과 정확한 출력 바이트를 각각 검증한다.
