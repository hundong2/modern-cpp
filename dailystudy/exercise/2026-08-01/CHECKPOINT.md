# 초보자 검증 체크포인트

## 1단계 — 말로 설명하기

- `std::string`은 문자를 소유하지만 `std::string_view`는 주소와 길이만 빌린다고 설명한다.
- `string_view`가 가리키는 원본이 먼저 파괴되면 댕글링 뷰가 된다고 설명한다.
- `struct`의 기본 접근은 `public`, `class`의 기본 접근은 `private`라고 말한다.
- 생성자에는 반환형이 없으며, 매개변수와 멤버 초기화 목록의 역할을 구분한다.
- `explicit`이 암시적 변환을 막고 `PrefixParser parser{Text{"say:"}}` 같은 직접 초기화는 허용한다고 설명한다.

통과 기준: 코드를 보지 않고 다섯 항목 중 네 항목 이상 설명한다.

## 2단계 — 코드에서 증거 찾기

- `Text` 별칭과 `unique_ptr<OutputPort>`의 템플릿 인자를 찾는다.
- lvalue(`input`), prvalue(`Command{...}`), xvalue(`std::move(output)`)를 각각 한 곳 표시한다.
- `const Text&` 참조 바인딩, `ParseResult*` 포인터, `nullptr` 비교를 찾는다.
- 복사 생략이 가능한 반환식과 소유권 이동이 실제로 일어나는 생성자 호출을 찾는다.
- 가상 간접 호출 후보와 일반 함수 호출을 구분한다.

통과 기준: 각 식의 값 범주뿐 아니라 객체 수명과 소유자를 함께 말한다.

## 3단계 — 수정하고 실행하기

1. `problem.cpp`의 TODO 1을 수정하기 전에 `matched`와 종료 코드를 예측한다.
2. TODO 2를 3회 반복으로 바꾸고 마지막 줄을 예측한다.
3. 빌드하고 두 실행 파일을 실행한다.
4. `main.cpp` 입력을 `quit`으로 바꾸면 왜 종료 코드가 1인지 설명한다.

통과 기준: 예측과 실제 결과가 다르면 조건식, 비교 연산자, 함수 호출 순서를 따라 원인을 설명한다.

## 최종 질문

`Command`가 `std::string argument` 대신 입력을 가리키는 `std::string_view argument`를 저장한다면 어떤 객체가 얼마나 오래 살아야 할까요? 서비스가 명령을 큐에 저장하는 구조로 바뀔 때는 왜 소유 문자열 복사가 더 안전할까요?

기계 실행 관점에서는 주소·길이 로드, 문자 비교, 분기, 저장, 함수 호출 및 가상 간접 호출이 생길 수 있습니다. 단, 실제 어셈블리 명령과 호출 제거 여부는 CPU, ABI, 컴파일러, 최적화 옵션에 따라 달라진다고 답해야 통과입니다.
