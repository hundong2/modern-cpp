# 2026-07-27 — C++20 삼방향 비교와 강한 값 타입

## 오늘의 목표

`operator<=>`(우주선 연산자)는 두 값을 한 번 비교해 작음·같음·큼의 관계를 표현한다. 오늘은 금액과 주문 우선순위를 원시 `int`로 흩어 놓지 않고 작은 값 객체에 모은다. 이 방식은 “비교 규칙은 도메인 타입이 책임진다”라는 아키텍처 경계를 만든다.

- `Money`는 음수가 될 수 없다는 불변식과 비교 규칙을 소유한다.
- `OrderPriority`는 등급과 접수 순서를 묶어 정렬 기준을 한곳에 둔다.
- `IOrderSink`는 애플리케이션이 출력 장치의 구체 타입을 몰라도 되게 하는 포트다.
- `ConsoleOrderSink`는 포트를 구현하는 어댑터다.

## 왜 `operator<=>`인가

```cpp
const Money cheap{1200};
const Money expensive{5000};
if (cheap < expensive) { /* ... */ }
```

컴파일러는 사용자 정의 `operator<=>`를 바탕으로 `<`, `>`, `<=`, `>=`를 다시 쓸 수 있다. `==`는 별도로 기본 선언한다. 비교 결과가 항상 완전한 순서를 이룰 때 반환 결과는 `std::strong_ordering`이다.

실행 시에는 보통 멤버 값을 메모리나 레지스터로 로드하고 비교한 뒤 조건 분기를 선택한다. 하지만 실제 명령과 인라이닝 여부는 CPU, ABI, 컴파일러, 최적화 옵션에 따라 달라지므로 특정 어셈블리 명령을 보장하지 않는다.

## 값 범주·수명·소유권 연결

- 이름이 있는 `cheap`은 lvalue다. `Money{1200}` 식은 prvalue이며 새 객체를 만든다.
- `const Money&`는 lvalue와 prvalue 모두에 바인딩할 수 있다. prvalue에 직접 바인딩된 const 참조는 그 참조의 범위까지 임시 객체 수명을 연장한다.
- `std::move(x)`는 이동 자체가 아니라 xvalue로 바꾸는 캐스트다. 실제 이동은 이동 생성자/대입 연산자가 선택될 때 일어난다.
- 이 값 객체는 `int`만 소유하므로 복사와 이동 비용이 작다. 포인터로 외부 자원을 소유하지 않는다.
- 함수가 지역 객체를 값으로 반환하면 복사 생략(NRVO)이 가능하다. C++17 이후 일부 prvalue 반환은 객체를 목적지에 직접 만든다.
- `IOrderSink&`는 비소유 참조다. 호출하는 동안 실제 어댑터 객체가 살아 있어야 한다.
