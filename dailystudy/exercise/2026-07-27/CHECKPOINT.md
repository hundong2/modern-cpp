# 초보자 검증 체크포인트

답을 외우지 말고 먼저 말로 설명한 뒤 코드를 바꿔 실행한다.

## 1단계 — 기초 문법

- `#include <compare>`와 `#include <iostream>`의 목적을 각각 설명한다.
- `int`, `std::size_t`, `std::string`이 어떤 값을 나타내는지 말한다.
- `Money{1200}`의 중괄호 초기화가 `Money price = 1200;`과 왜 다른지 설명한다.
- `publish_all`의 반환형, 두 매개변수, 실제 호출 위치를 찾는다.
- `const Money&`에서 `const`, `&`가 각각 무엇을 제한하고 무엇을 피하는지 말한다.
- 포인터가 참조와 달리 `nullptr`일 수 있음을 `sink_pointer`로 증명한다.

통과 기준: 각 답을 코드의 정확한 줄과 연결해 설명한다.

## 2단계 — 객체 문법

- `struct RawOrder`와 `class Money`의 기본 접근 차이를 말한다.
- `public`과 `private`이 외부 코드에 허용하는 접근을 설명한다.
- 멤버 변수 `amount_`가 객체 수명과 함께 존재함을 설명한다.
- 생성자에 반환형이 없고, 매개변수 `amount`가 호출 값을 받는다는 점을 찾는다.
- 멤버 초기화 목록이 생성자 본문보다 먼저 실행되는 이유를 말한다.
- `explicit`이 막는 암시적 변환과 허용하는 `Money{1200}` 직접 초기화를 각각 적는다.
- `using Won = int`가 새 타입을 만들지 않는다는 점을 설명한다.

통과 기준: `explicit`을 잠시 제거해 암시적 변환이 허용되는 예를 컴파일하고 다시 복구한다.

## 3단계 — 비교와 템플릿

- `operator<=>`가 `<` 비교에 어떻게 연결되는지 설명한다.
- `std::strong_ordering`이 부분 순서가 아닌 완전한 순서임을 말한다.
- `smaller(cheap, expensive)`에서 템플릿 인자 `T`가 무엇인지 답한다.
- `std::tie`, `std::sort`, `front`, `size` 표준 라이브러리 함수의 역할을 찾는다.
- `-`, `<`, `!=`, `&&`, `?:`, `<<`, `->` 연산자의 실제 등장 위치와 의미를 말한다.

통과 기준: `problem.cpp`의 정렬 방향을 바꿔 출력 순서가 예상대로 변하는지 확인한다.

## 4단계 — 값 범주와 수명

- 이름 있는 `cheap`이 lvalue이고 `Money{1200}`이 prvalue인 이유를 말한다.
- `std::move(orders)`가 xvalue를 만들지만 그 자체로 이동하지 않는다는 점을 설명한다.
- 이동 뒤 vector 저장소의 소유권이 어느 객체로 넘어가는지 말한다.
- `temporary_lifetime_extended`가 임시 객체의 수명을 어떻게 연장하는지 설명한다.
- `make_orders` 반환에서 NRVO와 복사 생략이 가능한 지점을 찾는다.
- `IOrderSink&`가 비소유 참조이므로 지켜야 할 수명 조건을 말한다.

통과 기준: 복사 생성자와 이동 생성자를 출력하는 작은 추적 타입을 만들어 호출 횟수를 관찰한다. 최적화와 복사 생략 때문에 예상보다 적을 수 있음을 함께 설명한다.

## 5단계 — 아키텍처와 기계 관점

- 비교 규칙을 호출부가 아니라 값 객체에 둘 때 중복이 줄어드는 이유를 말한다.
- `IOrderSink`가 포트이고 `ConsoleOrderSink`가 어댑터인 이유를 설명한다.
- 가상 호출이 런타임 실제 타입을 간접 선택할 수 있음을 설명한다.
- 값 비교가 로드·비교·조건 분기로, 함수가 호출/복귀로 구현될 수 있다고 설명한다.
- 실제 명령은 CPU, ABI, 컴파일러, 최적화 옵션에 따라 달라 특정 어셈블리 명령으로 단정할 수 없다고 덧붙인다.

통과 기준: 출력을 문자열 vector에 저장하는 새 어댑터를 만들고 `publish_all`을 고치지 않은 채 교체한다.
