# 자주까먹는 폴더 작업 지침

## 적용 범위

- 이 파일의 지침은 이 파일이 있는 `자주까먹는` 폴더와 모든 하위 폴더에만 적용한다.
- 사용자가 사이트 주소, 문서 내용, C++ 문법 또는 기술 주제를 제공하면 아래 절차에
  따라 독립적으로 학습할 수 있는 자료를 만든다.
- 기존 자료와 사용자 변경 사항을 보존하고, 새 주제가 기존 주제와 겹치면 무조건
  덮어쓰지 말고 기존 문서를 확장하거나 중복을 피할 수 있는 구성을 선택한다.

## 자료 조사와 정확성

- URL이 제공되면 원문을 확인하고, 문서의 제목, 다루는 C++ 표준 버전, 핵심 주장과
  예제의 전제 조건을 파악한 뒤 자료를 작성한다.
- 출처의 코드를 그대로 복제하기보다 저작권을 지키며 핵심 내용을 한국어로 설명하고,
  필요한 코드는 직접 작성한 최소 재현 예제와 실무형 예제로 구성한다.
- 표준 문법과 라이브러리 동작은 C++17 이상을 기준으로 한다. C++20 또는 C++23 기능을
  사용하면 각 파일과 문서에 필요한 표준 버전 및 C++17 대안을 명시한다.
- 컴파일러, 운영체제, ABI에 따라 달라지는 내용은 표준이 보장하는 부분과 구현 세부
  사항을 구분한다. 어셈블리 결과는 컴파일러, 버전, 아키텍처, 최적화 옵션에 따라
  달라질 수 있음을 함께 설명한다.
- 외부 자료를 사용한 경우 각 주제의 `README.md`에 원문 링크와 접근 목적을 기록한다.

## 폴더와 파일 구성

- 주제를 짧고 의미 있는 `kebab-case` 영문 폴더명으로 정한다. 예를 들어 이동 의미론은
  `move-semantics`, 원자적 메모리 순서는 `atomic-memory-order`로 만든다.
- 이름만으로 내용을 구분하기 어려우면 기술 이름을 우선하고, 같은 이름이 이미 있으면
  더 구체적인 하위 개념을 이름에 포함한다.
- 각 주제 폴더에는 최소한 다음 파일을 만든다.
  - `README.md`: 한국어 학습 가이드, 원문 번역 또는 상세 설명, 학습 순서와 파일 목차
  - `compare.md`: 동일 개념이 C#과 Python에서 어떻게 다른지 설명하는 비교 문서
  - `example.cpp`: 개념을 단계별로 보여 주는 설명용 실행 예제
  - `exercise.cpp`: 학습자가 수정하거나 결과를 예측하며 연습할 수 있는 실습 코드
- 개념이 크면 `notes.md`, 여러 개의 `.cpp` 파일, 헤더, 테스트, `CMakeLists.txt`를
  추가할 수 있다. 각 파일의 역할은 주제 `README.md` 목차에 반드시 기록한다.
- 최상위 `자주까먹는/README.md`의 자료 목차에 새 주제의 링크, 학습 목표,
  `compare.md`, 생성된 코드 파일 링크를 추가한다.

## README.md 작성 기준

- 기초 지식이 없는 사람도 순서대로 읽을 수 있도록 다음 흐름을 기본으로 한다.
  1. 무엇을 배우는지와 언제 사용하는지
  2. 먼저 알아야 할 용어와 최소 문법
  3. 소스 코드가 전처리, 컴파일, 어셈블, 링크되는 과정
  4. 객체 수명, 메모리 배치, 스택/힙, 레지스터 관점의 동작
  5. 대표적인 실수, 정의되지 않은 동작, 수명과 동시성 위험
  6. 실무에서 자주 쓰는 안전한 패턴과 선택 기준
  7. 빌드 및 실행 방법, 예상 출력, 결과를 확인하는 방법
  8. 생성된 모든 문서와 코드 파일의 학습 순서별 목차
- 번역이 필요한 원문은 문장 대 문장 전체 복사 대신 의미가 보존된 한국어 설명으로
  재구성한다. 필요한 전문 용어에는 영문 원어를 병기한다.
- 컴파일 명령은 사용 표준을 드러내야 한다. 예: `g++ -std=c++17 -Wall -Wextra
  -Wpedantic example.cpp -o example`.
- 어셈블리 확인이 유용하면 `-S`, `-O0`, `-O2` 등의 명령과 관찰할 명령어 또는
  호출 규약을 안내한다. C++ 한 줄이 항상 어셈블리 한 줄에 대응하지 않는 이유와
  최적화로 코드가 제거·인라인·재배치될 수 있다는 점도 설명한다.

## C++ 코드 작성 기준

- 최소 C++17로 컴파일 가능하게 작성하며, 더 최신 표준이 주제 자체인 경우에만 해당
  표준을 사용한다.
- 소유권은 RAII와 `std::unique_ptr`를 기본으로 표현하고, 공유 소유가 실제로 필요할
  때만 `std::shared_ptr`를 사용한다. raw pointer와 reference는 비소유 관찰임을 명확히 한다.
- 표준 컨테이너, 알고리즘, 범위 기반 반복, `constexpr`, 강한 타입, 구조화된 바인딩,
  `std::optional`, `std::variant`, `std::string_view` 등 의도가 선명한 현대적 기능을
  주제와 수명 조건에 맞게 사용한다.
- 전역 가변 상태, 수동 `new`/`delete`, C 스타일 캐스트, 매크로 기반 상수, 불필요한
  복사와 숨은 소유권을 피한다.
- 경고를 활성화해 빌드하고, 예제는 가능한 한 경고 없이 컴파일되고 직접 실행되어야 한다.
- 설명용 코드와 실습 코드 모두 각 코드 라인에 상세한 한국어 주석을 단다. 중괄호나
  단순 종료 라인도 블록 종료의 의미를 알 수 있게 주석을 붙이되, 주석 때문에 문법이나
  가독성이 깨지지 않도록 한다.
- 주석은 단순히 문법을 한국어로 읽는 데 그치지 않고 그 줄의 목적, 타입, 값 범주,
  객체 수명, 소유권, 예외 안전성, 메모리 접근, 예상 비용 중 관련 내용을 설명한다.
- 핵심 줄에는 가능한 범위에서 컴파일러가 만드는 load/store, 레지스터 전달, 함수 호출,
  분기, 스택 프레임, 힙 할당과 해제까지 연결해 설명한다. 특정 어셈블리 명령을 단정할
  때는 대상 아키텍처와 빌드 옵션을 명시한다.

## example.cpp와 exercise.cpp 기준

- `example.cpp`는 최소 예제에서 실무 패턴으로 진행하며, 실행 결과만 보고도 각 단계의
  차이를 확인할 수 있게 만든다.
- `exercise.cpp`는 TODO, 결과 예측 질문, 안전하지 않은 코드를 고치는 과제 중 적어도
  하나를 포함한다. 학습 가능한 기본 상태를 유지하고, 의도적으로 컴파일 오류나
  정의되지 않은 동작을 실행하는 코드는 비활성화하거나 별도 설명으로 격리한다.
- 정답이나 해설이 필요하면 `solution.cpp` 또는 README의 접힌 해설 구역을 추가하고
  목차에 연결한다.

## compare.md 작성 기준

- C++ 개념을 C#과 Python에서 가장 가까운 기능과 각각 비교한다.
- 단순 문법 표에 그치지 않고 다음 차이를 구체적인 짧은 코드와 함께 설명한다.
  - 타입 시스템과 컴파일/실행 모델
  - 값 형식과 참조 형식, 객체 수명, 가비지 컬렉션과 RAII
  - 복사, 이동, 참조, 가변성과 소유권 표현
  - 제네릭/템플릿과 런타임 또는 컴파일 타임 다형성
  - 예외, 오류 전달, 동시성 및 메모리 모델 중 주제와 관련된 항목
  - 성능 비용, 메모리 배치, FFI 또는 네이티브 호출 시 주의점
- “C# 또는 Python에는 없다”로 끝내지 말고 가장 가까운 관용적 대안, 동작 차이,
  해당 언어 사용자가 C++에서 흔히 하는 실수를 설명한다.

## 검증과 완료 조건

- 생성하거나 수정한 모든 C++ 파일을 명시한 표준 버전으로 컴파일하고 실행 가능한
  예제는 실행해 예상 출력과 일치하는지 확인한다.
- 가능하면 CMake 또는 저장소의 기존 빌드 방식을 사용하고, 사용한 명령을 주제
  `README.md`에 남긴다.
- 문서 링크가 실제 파일을 가리키는지, 주제 README와 최상위 README 목차에 누락된
  파일이 없는지 확인한다.
- 다음 항목을 모두 만족해야 작업이 끝난다.
  - 의미 있는 주제 폴더가 생성됨
  - 한국어 학습 가이드와 원문 링크/설명이 있음
  - 설명 코드와 실습 코드가 있고 상세한 라인 단위 주석이 있음
  - 기초 문법부터 메모리 및 어셈블리 레이어까지 연결해 설명함
  - `compare.md`에 C#, Python 차이와 실무 주의점이 있음
  - 생성된 파일이 두 단계의 README 목차에 모두 연결됨
  - 코드 빌드/실행과 문서 링크를 검증함
