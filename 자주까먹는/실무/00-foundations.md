# 0장: 컴퓨터와 C++ 실행 모델

## 30초 요약

C++ 소스는 바로 실행되지 않는다. [전처리기](wiki/build-pipeline.md)가 `#include`와 매크로를 처리하고, 컴파일러가 번역 단위마다 기계어를 만들며, [링커](wiki/build-pipeline.md)가 이를 라이브러리와 결합해 실행 파일을 만든다. 실행하면 운영체제가 [프로세스](wiki/process-thread.md)를 만들고 코드·전역 데이터·[스택과 힙](wiki/memory.md)을 위한 가상 주소 공간을 제공한다.

```text
source.cpp -> 전처리 -> 컴파일 -> object file -> 링크 -> executable
                                                        |
                                                        v
                                               OS가 프로세스 생성
```

## 꼭 알아야 할 최소 문법

- `int x = 3;`: `int` 타입 객체 `x`를 생성하고 3으로 초기화한다.
- `const T& ref`: 객체를 복사하지 않고 읽기 전용 별명으로 본다. [참조](wiki/value-categories.md) 자체가 소유자는 아니다.
- `{ ... }`: [스코프](wiki/memory.md)를 만든다. 자동 저장 기간 객체는 닫는 중괄호에서 역순으로 파괴된다.
- `T* p`: 주소를 보관한다. raw pointer만으로는 소유권을 알 수 없으므로 실무에서는 관찰 포인터인지 주석/타입으로 밝힌다.
- `if`, `for`, `while`: 분기와 반복을 만든다. 네트워크 루프는 종료 조건과 오류 경로가 특히 중요하다.

## 메모리는 '스택 대 힙'보다 수명으로 생각한다

`std::string name;` 같은 지역 객체는 스코프를 나가면 자동 파괴된다. `new`로 만든 객체는 대응하는 `delete`가 필요하지만, 현대 C++에서는 [RAII](wiki/raii.md) 객체와 `std::unique_ptr`가 해제를 책임지게 한다. `std::vector` 객체 자체는 지역 변수일 수 있지만 내부 원소 저장 공간은 동적 메모리에 있을 수 있다. 따라서 “객체는 스택, 데이터는 힙” 같은 단순 암기보다 **누가 언제 파괴하는가**를 추적한다.

## 운영체제 경계

`socket`, `read`, `write`, `epoll_wait`는 C++ 언어 기능이 아니라 운영체제 [시스템 호출](wiki/system-call.md) 인터페이스다. 호출 시 사용자 모드에서 커널 모드로 넘어가며, 실패는 예외 대신 반환값과 `errno`로 알려주는 경우가 많다. Windows의 Winsock/IOCP와 POSIX API는 이름과 수명 규칙이 다르다.

## 초보자 관찰 순서

1. `main()`에서 시작한다.
2. 각 변수의 타입, 소유자, 유효 스코프를 표시한다.
3. 함수 호출 때 값/참조/포인터 중 무엇이 전달되는지 본다.
4. 실패할 수 있는 연산의 반환값이 검사되는지 본다.
5. 정상 경로뿐 아니라 조기 `return`, 예외, 연결 종료에서 자원이 정리되는지 본다.
6. 여러 스레드가 같은 메모리를 만지는지, 그렇다면 [동기화](wiki/concurrency.md)가 있는지 본다.
